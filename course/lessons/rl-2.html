Value functions & the Bellman equation

Lesson 2 of Reinforcement learning

A good chess player doesn't calculate every game to the end. They glance at a position and know it's good. A value function is that instinct written as a number, and the Bellman equation is the one-line rule that lets you compute it.

From returns to values

In the 1950s Richard Bellman, a mathematician at the RAND Corporation, was working on multi-stage decision problems: how to schedule, stock or steer when every choice changes the next situation. His insight, published as Dynamic Programming (1957), was that you never need to plan a whole sequence at once. If you know how good every situation is, each decision becomes a one-step choice. RL inherited this idea almost unchanged.

The return $G_t$ from the last lesson is random: it depends on which actions the policy happens to sample and how the environment responds. So we define values as expected returns:

$$V^\pi(s) = \mathbb{E}_\pi\big[\,G_t \mid s_t = s\,\big] \qquad Q^\pi(s,a) = \mathbb{E}_\pi\big[\,G_t \mid s_t = s,\ a_t = a\,\big]$$
  • $V^\pi(s)$, the state value: how much return you expect starting in $s$ and then following policy $\pi$.
  • $Q^\pi(s,a)$, the action value: the same, but you first take action $a$ (whatever $\pi$ would have done), then follow $\pi$.

The two are tied together: the value of a state is the policy-weighted average of its action values, $V^\pi(s) = \sum_a \pi(a \mid s)\, Q^\pi(s,a)$. For example, if $\pi$ goes right with probability 0.7 (worth $Q = 1.0$) and up with probability 0.3 (worth $Q = 0.5$), then $V = 0.7 + 0.15 = 0.85$.

Why care about $Q$? Because it lets you compare actions without a model of the environment: just pick the action with the largest $Q(s,a)$. Q-learning (next lesson) is built entirely on it.

A policy in state $s$ takes action $a_1$ with probability 0.5 ($Q = 2$) and $a_2$ with probability 0.5 ($Q = 0$). What is $V^\pi(s)$?

  1. 2
  2. 0
  3. 1
  4. 0.5
$V^\pi(s) = \sum_a \pi(a \mid s)\,Q^\pi(s,a) = 0.5 \times 2 + 0.5 \times 0 = 1$.

The Bellman expectation equation

Take the recursion $G_t = r_{t+1} + \gamma\,G_{t+1}$ and average both sides over what the policy and the environment might do. You get the Bellman expectation equation:

$$V^\pi(s) = \sum_a \pi(a \mid s) \sum_{s'} P(s' \mid s, a)\,\Big[\, r(s,a,s') + \gamma\, V^\pi(s') \,\Big]$$
  • $\sum_a \pi(a \mid s)$: average over the actions the policy might take.
  • $\sum_{s'} P(s' \mid s,a)$: average over where the environment might send you. In our deterministic gridworld there is only one $s'$ per action.
  • $r(s,a,s') + \gamma V^\pi(s')$: the reward for this step, plus the discounted value of where you land.

It says: a state's value equals the expected reward of one step plus the discounted value of the next state. It's a consistency condition. The true values are the numbers that satisfy it in every state at once.

Worked example

The cell just left of the goal, under a dithering policy: 50% right (into the goal, $+1$, episode over), 50% up (bumps the edge and stays put, reward 0). $\gamma = 0.9$.

  1. Right: $1 + 0.9 \times 0 = 1$ (a terminal state has value 0).
  2. Up: $0 + 0.9 \times V$, where $V$ is this same cell's value.
  3. Bellman: $V = 0.5 \times 1 + 0.5 \times 0.9\,V = 0.5 + 0.45\,V$.
  4. Solve: $0.55\,V = 0.5$, so $V = 0.909$. Lower than 1.0, because dithering wastes time and time is discounted.

With many states this is a system of linear equations, one per state. You can solve it directly, or just apply the equation over and over as an update until the numbers stop changing (iterative policy evaluation).

In the worked example, the policy changes to 90% right and 10% up. What happens to $V$?

  1. It rises toward 1, because less time is wasted
  2. It stays at 0.909
  3. It falls, because up is safer
  4. It becomes exactly 1
$V = 0.9 + 0.1 \times 0.9\,V$ gives $V = 0.9 / 0.91 \approx 0.989$. Closer to 1, but not quite: the 10% of bumps still costs a little discounting.

Optimal values and value iteration

We don't just want to evaluate a policy, we want the best one. Its values $V^*$ satisfy the Bellman optimality equation, which swaps the policy's average for a max:

$$V^*(s) = \max_a \sum_{s'} P(s' \mid s, a)\,\Big[\, r(s,a,s') + \gamma\, V^*(s') \,\Big] \qquad Q^*(s,a) = \sum_{s'} P(s' \mid s,a)\Big[\, r + \gamma \max_{a'} Q^*(s',a') \,\Big]$$

Best value now = best action's (reward + discounted best value next). The max makes the equations non-linear, but there's a simple way to solve them: value iteration (Bellman, 1957). Start from $V = 0$ and repeatedly sweep through every state, replacing its value with the right-hand side. Each sweep is a Bellman backup; for $\gamma < 1$ the values are guaranteed to converge to $V^*$.

Once you have $V^*$, the optimal policy is the greedy one: in each state take $\arg\max_a \big[r + \gamma V^*(s')\big]$. No search over whole paths is needed; the values already did the long-range thinking.

Explain like I'm 5

Imagine a treasure map made of squares. The square right next to the treasure chest glows brightest. Its neighbours glow a little less, their neighbours a little less again, and so on across the map.

Now an explorer standing anywhere doesn't need the whole route. They just look at the squares around them and step onto the brightest one. Step after step, the glow leads them to the treasure.

The glow is the value. Lighting up the map one ring at a time, outwards from the chest, is value iteration.

Where it breaks: a real map doesn't change, but values depend on the policy and on $\gamma$, and in a random world a bright square can still sit next to a pit you might slip into.

What is the difference between the Bellman expectation and optimality equations?

  1. The optimality equation has no discount factor
  2. The expectation equation averages over the policy's actions; the optimality equation takes the max over actions
  3. Only the optimality equation uses the next state's value
  4. They are the same equation written two ways
$\sum_a \pi(a \mid s)\,[\dots]$ evaluates a given policy; $\max_a [\dots]$ describes the best possible policy. Both use the reward plus the discounted next value.

How γ shapes the values, and where tables stop

In our deterministic gridworld with $\gamma = 0.9$, every value is just $\gamma^{d-1}$, where $d$ is the number of moves to the goal. Change $\gamma$ and the whole picture changes. Try it:

Playground: turn the discount knob

Value iteration runs to convergence for the $\gamma$ you choose. Watch the values and the arrows; then try exactly 1.

Two lessons hide in that knob. A small $\gamma$ makes far-away rewards nearly invisible; a $\gamma$ of exactly 1 with no cost per step makes the agent indifferent to when it arrives, so it may wander. Practical tasks either keep $\gamma < 1$ or add a small negative reward per step.

Where tables stop. Value iteration needs two things we rarely have. First, a model: the transition probabilities $P(s' \mid s,a)$ and rewards, so it can compute the backup. Second, a sweep over every state. Our gridworld has 13 non-terminal states; Go has roughly $2 \times 10^{170}$ legal positions. Bellman himself named this the curse of dimensionality. The rest of the module is about escaping it: learn from sampled experience instead of a model (Q-learning, RL.3), and replace the table with a neural network that generalizes across states (DQN, RL.3; actor-critic, RL.5).

Why this matters for LLMs: for a language model the state is the prompt plus every token so far, so the number of states is astronomically larger than Go's. No table could hold them. Yet values still appear: PPO-based RLHF trains a value model (the critic) that predicts $V^\pi$ at every token of a response, a neural network standing in for the table (see RLHF with PPO). GRPO (M3.5) avoids learning $V$ altogether by using the average reward of a group of samples as the baseline. And verifiers that score partial reasoning, process reward models (RS.4), are in effect value estimates for half-finished answers.

Why can't we simply run value iteration for chess?

  1. Chess has no rewards
  2. The Bellman equation only works for gridworlds
  3. Chess is not a Markov decision process
  4. There are far too many states to sweep through and store in a table
The board position is Markov (with a few extras such as castling rights) and the reward is win/lose. The problem is scale: a table over every position is impossible, which is why game-playing systems learn value networks (RL.6).
Explain it back · in two or three sentences

Explain how value iteration finds the best policy in the gridworld, starting from all-zero values.

Model answer: Each sweep replaces every cell's value by the best one-step option, $\max_a [r + \gamma V(s')]$, using the previous values. Value spreads outward from the goal one move per sweep, shrinking by $\gamma$ each step, until nothing changes ($V^*$). Then the best policy just picks, in each cell, the action with the highest $r + \gamma V^*(s')$.

Connect to RL.1: which identity is the Bellman expectation equation built on?

  1. $G_t = r_{t+1} + \gamma\,G_{t+1}$
  2. $G_t = \sum_k r_{t+k+1}$ with no discount
  3. $\pi(a \mid s) = 1$ for one action
  4. $Q(a) \leftarrow Q(a) + \frac{1}{N}(r - Q(a))$
Take expectations of the return recursion: the expected return now equals the expected next reward plus $\gamma$ times the expected return (value) from the next state.

After value iteration converges, how do you get the optimal policy?

  1. Run value iteration again with $\gamma = 1$
  2. Pick actions uniformly at random
  3. Choose the action leading to the state with the most visits
  4. In each state, pick $\arg\max_a [r + \gamma V^*(s')]$
Greedy extraction: a one-step look-ahead with the optimal values gives an optimal policy.

What does value iteration need that Q-learning (next lesson) does not?

  1. A discount factor
  2. A model of the environment: the transition probabilities and rewards for every state and action
  3. A reward signal
  4. A policy
The backup sums over $P(s' \mid s,a)$. Q-learning gets the same effect from sampled transitions, without ever knowing $P$.

Key takeaways

  • $V^\pi(s)$ and $Q^\pi(s,a)$ are expected returns from a state, or from a state-action pair; $V^\pi(s) = \sum_a \pi(a \mid s)\,Q^\pi(s,a)$.
  • Bellman expectation: value = expected (reward + $\gamma$ × next value) under the policy. Bellman optimality: the same with a max over actions.
  • Value iteration repeats the optimality backup from $V = 0$; value flows back from the goal and converges to $V^*$.
  • The greedy policy on $V^*$ is optimal. $\gamma$ sets how far ahead the agent cares.
  • Tables and known models don't scale; learning from samples and neural networks do.
