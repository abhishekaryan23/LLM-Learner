Vision Transformers: images as patches

Lesson 1 of Vision

For a decade, computer vision meant convolutional networks. In 2020 a Google team showed that you can cut an image into squares, treat each square like a word, and hand the result to an almost unmodified Transformer. That idea, the Vision Transformer (ViT), is now inside image search, multimodal LLMs and video generators.

By the end you can

  • Turn an image into ViT tokens step by step, and count them for any resolution and patch size.
  • Explain what the patch embedding, the [CLS] token and the position embeddings each do.
  • Explain why ViTs need more data than CNNs, and how DeiT and Swin responded.

Warm-up · guess before you learn

Guess first. A wrong guess now makes the right answer stick later.

A 224 × 224 image is cut into non-overlapping 16 × 16-pixel squares. How many squares is that?

  1. 14
  2. 196
  3. 256
  4. 50,176
224 / 16 = 14 squares per side, and 14 × 14 = 196. (256 is what you get with 14 × 14-pixel squares; 50,176 is the number of pixels.)

A Transformer and a CNN of similar size are both trained from scratch on ImageNet's 1.3 million labelled images, with no special tricks. What usually happens?

  1. The Transformer wins easily, because attention is more powerful
  2. They tie, because size is all that matters
  3. The CNN wins, because its built-in assumptions about images make up for limited data
  4. The Transformer can't be trained on images at all
This is the original ViT paper's finding. A CNN "knows" that nearby pixels belong together; a ViT has to learn that from data. With hundreds of millions of images the ViT catches up and passes the CNN.

Why CNNs ruled vision, and what ViT changed

In 2012, AlexNet (Krizhevsky, Sutskever & Hinton) won the ImageNet challenge with a top-5 error of about 15%, against about 26% for the runner-up. Every winner after it was a convolutional network: VGG, GoogLeNet, then ResNet (He et al., 2015), whose residual connections made networks with 100+ layers trainable.

CNNs won because they bake in two facts about images, which you met in P6.1:

  • Locality: a filter only looks at a small neighbourhood, say 3 × 3 pixels. Nearby pixels matter most.
  • Weight sharing: the same filter slides over the whole image, so a cat's ear is detected the same way anywhere (translation equivariance).

These built-in assumptions are called inductive biases. They save data, but they also limit what a layer can see: an early layer cannot relate a pixel in the top-left corner to one in the bottom-right. Only after many layers does the receptive field cover the whole image.

Meanwhile, in language, Transformers (Vaswani et al., 2017) were replacing everything. Researchers tried bolting attention onto CNNs, but attention over every pixel is hopeless: a 224 × 224 image has 50,176 pixels, so about 2.5 billion pixel pairs per attention layer.

Dosovitskiy et al. (2020), in a paper titled An Image is Worth 16x16 Words, made the radical simple move: cut the image into 16 × 16-pixel patches, treat each patch as a token, and feed the sequence to a standard Transformer encoder with almost no image-specific machinery. That model is the Vision Transformer (ViT).

Which property does a ViT layer have that an early CNN layer does not?

  1. Any patch can directly use information from any other patch, however far apart
  2. The same weights are applied at every position in the image
  3. It works on raw pixels instead of learned features
Self-attention connects every token to every other token in one layer, so the "receptive field" is the whole image from layer 1. Weight sharing across positions is true of both (ViT applies the same patch embedding and the same blocks to every token).

From pixels to tokens

A ViT needs a sequence of vectors, just like a language model. Here's how an image becomes one. Step through it:

In symbols, with patches $x_p^1, \dots, x_p^N$, each flattened to a row of $P^2 C$ numbers:

$$z_0 = \big[\,x_{\text{cls}};\; x_p^1 E;\; \dots;\; x_p^N E\,\big] + E_{\text{pos}}$$

$P$ is the patch side (16) and $C$ the number of colour channels (3). $E$ is a learned $P^2C \times D$ matrix shared by all patches, and $D$ is the model width (768 for ViT-Base). $x_{\text{cls}}$ is a learned $D$-dimensional vector, and $E_{\text{pos}}$ is a learned $(N{+}1) \times D$ table with one row per position. The square brackets stack the rows into an $(N{+}1) \times D$ matrix $z_0$, the input to layer 1.

  • Patch embedding. Multiplying every flattened patch by the same $E$ is exactly a convolution with a 16 × 16 kernel and stride 16, which is how most code implements it.
  • [CLS] token. Borrowed from BERT: a learned token with no image content. Through attention it gathers a summary of all patches, and its final vector feeds the classifier.
  • Position embeddings. Attention ignores order (M1.3), so without them the ViT would see a bag of shuffled patches. ViT simply learns one vector per position; the paper found that fancier 2-D schemes helped very little.
Explain like I'm 5

Take a photo of a cat and cut it into square jigsaw pieces. Lay them out in one long row, like words in a sentence.

Before you mix them up, put a coloured dot on each piece so you remember where it came from. Those dots are the position embeddings.

Now a reader who is very good at sentences can "read" the row and say: that's a cat! Where it breaks: the real model doesn't see the pieces as pictures; each piece becomes a list of numbers, and it learns what the dots mean during training.

Worked example: ViT-B/16 at 224 × 224

  1. Patches: $224/16 = 14$ per side, so $N = 14 \times 14 = 196$.
  2. Values per patch: $16 \times 16 \times 3 = 768$.
  3. Sequence length: $196 + 1 = 197$ tokens, including [CLS].
  4. Patch-embedding parameters: $E$ is $768 \times 768$, plus 768 biases $= 590{,}592$. The position table adds $197 \times 768 = 151{,}296$. Both are tiny next to ViT-B's roughly 86M parameters.

A ViT was trained with no position embeddings. You shuffle its input patches. How does the [CLS] output change?

  1. It becomes random noise
  2. It changes a lot, because attention depends on the order of tokens
  3. Nothing: without position embeddings, the encoder treats the patches as an unordered set
Self-attention and the per-token MLP are permutation-equivariant, so shuffling the patch tokens only shuffles their outputs, and [CLS], which attends to all of them, gets exactly the same result. Position embeddings are the only source of "where".

A plain Transformer encoder, and its appetite for data

After the embedding, a ViT is the encoder you already know from M1.4: pre-norm LayerNorm, multi-head self-attention, a GELU MLP, residual adds. The one change is that there is no causal mask. A decoder LLM must not peek at future words, but an image has no "future": every patch may attend to every patch.

The paper's three sizes set names still used today:

  • ViT-Base: 12 layers, $D = 768$, 12 heads, about 86M parameters.
  • ViT-Large: 24 layers, $D = 1024$, 16 heads, about 307M.
  • ViT-Huge: 32 layers, $D = 1280$, 16 heads, about 632M.

The suffix is the patch size: ViT-L/14 uses 14 × 14 patches, so a 224-pixel image gives $16 \times 16 = 256$ patches.

The catch: data. Trained on ImageNet-1k alone (1.3M images), ViTs did worse than ResNets of similar size. They only pulled ahead when pretrained on much larger datasets: ImageNet-21k (14M images) or Google's internal JFT-300M (about 300M images). After JFT pretraining, ViT-H/14 reached 88.55% top-1 accuracy on ImageNet, matching or beating the best CNNs while using less pretraining compute. The lesson: weaker inductive bias means the model must learn locality from examples, and at scale, learning it beats hard-coding it.

DeiT (Touvron et al., 2021) showed the data problem could also be engineered around. Using ImageNet-1k only, with heavy augmentation (RandAugment, Mixup, CutMix), strong regularization and a distillation token that learns from a CNN teacher, DeiT-B reached 81.8% top-1 (83.4% with the distillation token), trained on one multi-GPU machine in under three days. Today the main answer is self-supervised pretraining on unlabelled images, which is the subject of V1.3.

What do ViTs learn? The original paper found that some heads attend locally even in the lowest layers (rediscovering CNN-like behaviour), while others attend across the whole image from the start. The learned position embeddings even arrange themselves into a 2-D grid: patches in the same row or column get similar vectors.

Why did the original ViT need JFT-300M pretraining to beat ResNets?

  1. Transformers can't be trained with fewer than 100 million images
  2. With less built-in knowledge about images (locality, translation), it must learn those regularities from many more examples
  3. JFT images are higher resolution than ImageNet images
The CNN's inductive biases act like free training data. The ViT has to learn them, which takes more data; DeiT showed that strong augmentation and distillation can partly substitute for it.

More pixels, many more pairs

Keep the patch size fixed and the number of tokens grows with the image's area. Attention compares every token with every token, so its cost grows with the square of the token count (M1.1). Resolution gets expensive fast.

Worked example: 224 vs 448 pixels, 16-pixel patches

  1. 224 × 224: $14 \times 14 = 196$ patches, 197 tokens, $197^2 = 38{,}809$ attention scores per head per layer.
  2. 448 × 448: $28 \times 28 = 784$ patches, 785 tokens, $785^2 = 616{,}225$ scores.
  3. Ratio: twice the side means $4\times$ the tokens and about $616{,}225 / 38{,}809 \approx 15.9\times$ the attention work. The MLPs, which run once per token, cost $4\times$.

Two practical consequences:

  • Changing resolution. Models are usually pretrained at low resolution and fine-tuned at higher. The position table was learned for a 14 × 14 grid, so it is interpolated in 2-D to the new grid (say 24 × 24). This is one of the few image-specific tricks in ViT.
  • Hierarchical designs. Swin Transformer (Liu et al., 2021) uses small 4 × 4 patches but only attends inside local windows of 7 × 7 patches, shifting the windows in alternate layers so information crosses window borders. It merges neighbouring patches between stages, giving CNN-like feature maps at several scales, and its cost grows linearly with image area. That made it a strong backbone for detection and segmentation (V1.4).

The competition pushed CNNs too: ConvNeXt (Liu et al., 2022) modernized a ResNet with Transformer-era design choices and matched Swin. As of 2026, plain ViTs dominate large pretrained vision encoders, while CNNs and hybrids remain common where latency on small devices matters.

Why this matters for LLMs: when you send an image to a multimodal LLM, a ViT encoder (usually a CLIP- or SigLIP-style one, V1.2) turns it into patch vectors that are projected into the LLM's token space (MM.1). Each patch then costs context like a word does, which is why image-heavy prompts are slow and why many systems tile, resize or merge patches to control the token count. The same "patchify" idea extends to video as space-time patches (VD.1) and to diffusion transformers (G1.6).

You switch from 16-pixel to 8-pixel patches at the same 224 × 224 resolution. Roughly how does the attention cost change?

  1. It halves
  2. It grows 4×
  3. It grows about 16×
Halving the patch side gives 28 × 28 = 784 patches instead of 196, so 4× the tokens and about 16× the pairs. Smaller patches mean finer detail but quadratically more attention.
Explain it back · in two or three sentences

Explain to a friend how a ViT turns a photo into something a Transformer can read, and why it needs position embeddings.

Model answer: The photo is cut into fixed-size patches (16 × 16 pixels), each patch is flattened and multiplied by one shared learned matrix to get a vector, and a learned [CLS] token is put in front. Because attention treats its inputs as an unordered set, a learned position vector is added to each token so the model knows where each patch came from; then a standard Transformer encoder processes the sequence and the [CLS] output is classified.
Check yourself

In ViT-B/16, what exactly is the "linear patch embedding"?

  1. A small CNN that runs on each patch
  2. One learned 768 × $D$ matrix applied to every flattened 16·16·3 patch (equivalently, a stride-16 convolution)
  3. A lookup table with one vector per possible patch
  4. A fixed Fourier transform of each patch
It is a single shared linear map. There is no lookup table: unlike words, patches are continuous, so there is no finite vocabulary to look up.

A decoder LLM's attention uses a causal mask (M1.4). Why doesn't a ViT classifier use one?

  1. Images are too small to need it
  2. The mask is only needed when there are more than 1,000 tokens
  3. ViTs use convolutions instead of attention
  4. It isn't predicting the next token: the whole image is given at once, so every patch may look at every other patch
The causal mask exists so a model can't see the token it is about to predict. A classifier sees the whole input at once, so full bidirectional attention is allowed and useful.

A ViT pretrained at 224 × 224 is fine-tuned at 448 × 448 with the same patch size. What must change?

  1. The position embeddings, interpolated from a 14 × 14 to a 28 × 28 grid; the other weights can be reused
  2. The patch-embedding matrix, which must get bigger
  3. Nothing at all, and the cost stays the same
  4. The number of layers must double
All Transformer weights work on any number of tokens, and $E$ still sees 16 × 16 × 3 patches. Only the position table is tied to the grid size. The cost, of course, goes up about 16× in attention.

What problem was Swin Transformer mainly designed to fix?

  1. ViTs can't classify images
  2. ViTs need labelled data
  3. Global attention cost grows quadratically with image area, and a plain ViT gives only one scale of features
  4. ViTs can't use position embeddings
Swin's local, shifted windows make cost linear in area, and patch merging builds a multi-scale hierarchy that detection and segmentation heads expect.

Key takeaways

  • A ViT cuts an image into patches (224 px with 16-px patches gives 196), embeds each with one shared linear map, adds a [CLS] token and learned position embeddings.
  • The rest is a standard Transformer encoder with no causal mask; the [CLS] output feeds a classifier.
  • Weaker inductive bias than CNNs means ViTs need lots of data (JFT-300M) or tricks (DeiT's augmentation and distillation).
  • Tokens grow with image area and attention with tokens squared: doubling resolution costs about 16× in attention. Swin's windows make it linear.
