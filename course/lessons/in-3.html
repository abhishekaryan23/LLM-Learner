Sparse autoencoders

Lesson 3 of Interpretability

If a model stores features in superposition, can we pull them back apart? A sparse autoencoder (SAE) tries: it rewrites each dense activation as a combination of a few directions from a huge learned dictionary. Since 2023, SAEs have turned up millions of readable features inside production LLMs, and a famous bridge-obsessed Claude. They also have real limits.

By the end you can

  • Write the SAE objective (reconstruction + L1 sparsity), explain every symbol, and compute it for a small example.
  • Summarise what SAEs found at scale (Anthropic, OpenAI, Google DeepMind) and how features are used for steering and attribution graphs.
  • Name the main limitations: reconstruction error ("dark matter"), feature splitting and absorption, dead latents, and hard evaluation.

An LLM's activation has 4,096 numbers. A sparse autoencoder trained on it might have how many latent units?

  1. About 30, to compress it
  2. Tens of thousands to millions: many more than 4,096, with only a few active at a time
  3. Exactly 4,096, one per neuron
  4. One, the overall "meaning"
An SAE is overcomplete: wider than its input. Its job isn't compression but untangling superposed features, so it needs room for many more features than dimensions, kept in check by sparsity.

In 2024, Anthropic briefly released a Claude that brought up the Golden Gate Bridge in almost every answer. How was that done?

  1. Fine-tuning on bridge photos
  2. A hidden system prompt about the bridge
  3. Clamping one SAE feature, found in the model's activations, to a high value while it ran
  4. Deleting all other landmarks from its training data
The feature was found by a sparse autoencoder trained on Claude 3 Sonnet's activations. Turning it up at inference time steered the model, no training needed.

Dictionary learning: undoing superposition

In 1996, neuroscientists Bruno Olshausen and David Field asked what code the visual cortex might use. They trained a sparse coding model to describe small patches of natural images as a combination of as few "dictionary" patterns as possible, and the patterns it learned looked like the edge detectors found in real neurons. The general method, dictionary learning, assumes each data point $x$ is a sparse combination of directions from a learned dictionary, possibly with more directions than dimensions.

That is exactly the picture IN.1 painted of LLM activations: $h \approx \sum_i f_i d_i$ with mostly zero $f_i$ and more directions $d_i$ than neurons. In 2022–2023, researchers applied the idea to transformers using a sparse autoencoder (Sharkey et al., 2022; Cunningham et al., 2023; Bricken et al., 2023, "Towards Monosemanticity"). It is the autoencoder of P6.4 turned inside out: the code is much wider than the input, and the constraint is sparsity instead of a narrow bottleneck.

$$f = \mathrm{ReLU}\big(W_{\text{enc}}(x - b_{\text{dec}}) + b_{\text{enc}}\big), \qquad \hat{x} = W_{\text{dec}} f + b_{\text{dec}}$$ $$\mathcal{L} = \lVert x - \hat{x} \rVert_2^2 + \lambda \sum_{i=1}^{m} |f_i|$$
  • $x$: one activation vector from the LLM (e.g. the residual stream at one token), dimension $d$.
  • $f$: the $m$ latents (candidate features), with $m \gg d$. "Expansion factor" means $m/d$.
  • $W_{\text{enc}}, b_{\text{enc}}$: encoder weights and bias; the ReLU makes every $f_i \ge 0$, and most exactly 0.
  • $W_{\text{dec}}$: its $i$-th column is feature $i$'s direction $d_i$, usually kept at unit length. $b_{\text{dec}}$ is a bias (subtracted before encoding, added back after).
  • $\lVert x - \hat{x}\rVert_2^2$: reconstruction error, the sum of squared differences.
  • $\lambda \sum |f_i|$: the L1 sparsity penalty. Since $f_i \ge 0$, it is just $\lambda$ times the total activation. Bigger $\lambda$ means fewer active latents and worse reconstruction.

The LLM stays frozen. You run it over a large amount of text, save activations from one layer, and train the SAE on those. (Anthropic's 2024 version also multiplies each $|f_i|$ by its decoder column's length, so the model can't dodge the penalty by shrinking $f$ and growing $W_{\text{dec}}$.)

Worked example

$x = [1.0, -0.5, 0.2]$, the SAE outputs $\hat{x} = [0.9, -0.4, 0.2]$ using latents $f = [0, 1.2, 0, 0.5, 0, 0]$, and $\lambda = 0.01$.

  1. Reconstruction: $(0.1)^2 + (-0.1)^2 + 0^2 = 0.02$
  2. Sparsity: $\lambda \sum |f_i| = 0.01 \times (1.2 + 0.5) = 0.017$
  3. Loss: $0.02 + 0.017 = 0.037$. Two latents of six are active, an expansion factor of $6/3 = 2$. ✓

What happens as you increase the sparsity coefficient $\lambda$ in an SAE?

  1. Fewer latents are active per input, and reconstruction error goes up
  2. More latents are active, and reconstruction improves
  3. The SAE gets narrower
  4. Nothing; $\lambda$ only affects training speed
The L1 term charges for every unit of activation, so a larger $\lambda$ buys sparsity at the cost of reconstruction. Choosing $\lambda$ means choosing a point on that trade-off.

What SAEs found at scale

Towards Monosemanticity (Bricken et al., 2023) trained SAEs on the 512-neuron MLP layer of a one-layer transformer, using 8 billion activation samples and dictionaries from 512 to 131,072 latents. Their main 4,096-latent run produced features far more interpretable than the neurons: features for DNA sequences, Arabic script, legal language and many more. Bigger dictionaries showed feature splitting: one broad feature in a small SAE became several finer ones in a larger SAE.

Scaling Monosemanticity (Templeton et al., 2024) took the method to a production model, Claude 3 Sonnet, training SAEs with about 1 million, 4 million and 34 million latents on a middle layer's residual stream. Many features were abstract: the same feature fired for a concept across languages, and even for images of it. Some were safety-relevant, such as features for deception, sycophancy and security vulnerabilities in code. One feature responded to the Golden Gate Bridge. Clamping it to 10 times its maximum activation made the model talk about the bridge constantly, even describing itself as the bridge. Anthropic put this Golden Gate Claude online as a 24-hour demo in May 2024.

Other labs followed, with variations on the recipe:

  • OpenAI (Gao et al., 2024, "Scaling and evaluating sparse autoencoders") replaced ReLU + L1 with a TopK activation: keep only the $k$ largest latents and zero the rest, so sparsity is set directly and nothing is shrunk by a penalty. They found clean scaling laws, very few dead latents, and trained a 16-million-latent SAE on GPT-4 activations over 40 billion tokens.
  • Google DeepMind released Gemma Scope (Lieberum et al., 2024): open JumpReLU SAEs (a ReLU with a learned threshold per latent; Rajamanoharan et al., 2024) for every layer and sub-layer of Gemma 2 2B and 9B and some layers of 27B. Gemma Scope 2 (December 2025) covers the Gemma 3 family from 270M to 27B parameters and adds transcoders.
  • Open tools such as Neuronpedia host feature browsers for many open models, and features are labelled automatically by having an LLM read each feature's top examples (an idea from Bills et al., 2023).
Explain like I'm 5

A muddy beam of light looks like one brownish colour. Shine it through a prism and it spreads into lots of clean stripes on the wall. Only a few stripes are bright at any moment; the rest stay dark.

The model's activation is the muddy beam: everything mixed together. The SAE is the prism: it splits the mix into many clean features, and only a few are lit for any one word. Add the bright stripes back together and you get (almost) the beam you started with.

Where it breaks: a real prism is fixed physics and splits light perfectly. An SAE is learned, so which stripes it finds depends on its size and settings, and adding them back never gives exactly the original beam.

How does a TopK SAE (Gao et al., 2024) control sparsity?

  1. With a larger L1 coefficient
  2. By making the dictionary smaller
  3. By training on fewer tokens
  4. By keeping only the $k$ largest latents for each input and setting the rest to zero
Exactly $k$ latents are active per input, so you set the sparsity directly, and the kept latents aren't shrunk by an L1 penalty.

From features to circuits: attribution graphs

An SAE explains what one layer represents. To see how the model computes, you need to connect features across layers, the circuit idea of IN.2 with features instead of neurons. A transcoder (Dunefsky et al., 2024) helps: instead of reconstructing an MLP's input, it is trained to imitate the MLP itself, mapping its input to its output through a wide, sparse layer of features. A cross-layer transcoder lets each feature read from one layer and write to all later layers.

In March 2025 Anthropic published circuit tracing (Ameisen et al., 2025) and applied it to Claude 3.5 Haiku (Lindsey et al., 2025, "On the Biology of a Large Language Model"). They replace the model's MLPs with a cross-layer transcoder, then build an attribution graph for one prompt: nodes are the active features, and edges show how much each feature directly pushed each later feature and the output. Hypotheses read off the graph are then checked by intervening on the real model, as in IN.2. Among the findings:

  • Multi-step reasoning: for "the capital of the state containing Dallas", features for Texas light up in the middle of the computation before Austin is output.
  • Planning: when writing a rhyming couplet, the model picks candidate rhyme words before writing the line that ends with them.
  • Shared concepts: many features are language-independent, with language-specific features at the input and output.

The graphs are partial: they cover the computation the replacement model captures, and the authors report that they give satisfying explanations for only a fraction of the prompts they tried. In May 2025 the method was open-sourced as the circuit-tracer library, with interactive graphs on Neuronpedia for open models.

What does a transcoder learn, compared with an SAE?

  1. The same thing, under a different name
  2. An SAE reconstructs an activation; a transcoder imitates a layer, mapping the MLP's input to its output through sparse features
  3. A transcoder translates between languages
  4. A transcoder compresses the model's weights
Because a transcoder's features replace the MLP's computation, you can trace how features at one layer produce features at the next, which is what attribution graphs need.

Limits and open problems

SAEs changed interpretability, but they are an approximation of the model, not the model itself:

  • Reconstruction error ("dark matter"). $\hat{x}$ never equals $x$ exactly. Substitute the SAE's reconstruction back into the LLM and its next-token loss gets noticeably worse, so some of the computation lives in the error. Engels et al. (2024) found much of that error is predictable from the input, which hints at structure the SAEs miss.
  • Feature splitting and absorption. The features you get depend on dictionary size: "animal" in one SAE may be "dog", "cat" and "horse" in a bigger one. Worse, a broad feature can have holes where a narrower one "absorbs" it (Chanin et al., 2024), so a "starts with S" latent may stay silent on some S-words.
  • Dead latents. Some latents never fire, wasting capacity; the share grows with dictionary size. TopK training, auxiliary losses and careful initialisation reduce it.
  • Evaluation is hard. There is no ground truth for a real model's features. Benchmarks such as SAEBench (Karvonen et al., 2025) score SAEs on proxies like reconstruction, sparsity, probing and how cleanly concepts can be removed, and the proxies don't always agree.
  • Usefulness is debated. In March 2025 Google DeepMind's interpretability team reported that, for detecting harmful intent in prompts, simple linear probes on raw activations beat probes built on SAE features, and said it would deprioritise basic SAE research. Others continue to find SAEs and transcoders valuable for exploring a model when you don't know what to look for.

As of 2026 the field uses SAEs, transcoders, probes, patching and steering side by side: dictionaries to discover hypotheses, simpler targeted tools to test and deploy them. Try the central trade-off yourself:

Each dot is an SAE with 128 latents trained (in advance, in PyTorch) with a different L1 coefficient $\lambda$. Move the slider to pick one. The strip shows that SAE's latents for one test input that contains three true features.

With $\lambda = 0$ the SAE reconstructs almost perfectly but spreads every input over dozens of latents, and none of them matches a true feature. Moderate $\lambda$ recovers all 64 true directions. Very large $\lambda$ hurts reconstruction and starts losing features. Real SAEs face the same dial, just without an answer key.

Why this matters for LLMs: SAEs turned "the model has superposition" into a working method for listing millions of a production model's concepts, finding safety-relevant ones, and steering them directly. They have already been used, alongside behavioural evals (M4), in experiments that audit a model for a deliberately hidden objective (Marks et al., 2025). They are also a reminder of the field's honesty problem: an explanation is only as good as the share of the model it actually accounts for.

What is meant by an SAE's "dark matter"?

  1. Latents that never activate
  2. Features about astronomy
  3. The part of the activation the SAE fails to reconstruct, which still matters to the model's behaviour
  4. The decoder bias
The reconstruction error $x - \hat{x}$. Swapping in $\hat{x}$ for $x$ makes the LLM measurably worse, so the features found don't explain everything the model computes. (Never-firing latents are "dead latents".)
Explain it back · in two or three sentences

How does a sparse autoencoder try to undo superposition, and what is the trade-off it has to manage?

Model answer: It learns a dictionary with many more directions than the activation has dimensions, and encodes each activation as a sparse, non-negative combination of a few of them; trained on reconstruction error plus an L1 penalty, each direction tends to become one interpretable feature. The trade-off is between sparsity and reconstruction: a stronger penalty gives fewer, cleaner features but leaves more of the activation unexplained, and the unexplained part ("dark matter") may matter to the model.
Check yourself

Interleaving with P6.4: how does an SAE's code differ from a classic autoencoder's bottleneck?

  1. It is smaller than the input, to force compression
  2. It is much wider than the input, and sparsity (few active latents) does the constraining instead of narrowness
  3. It is the same size as the input
  4. It has no decoder
A narrow bottleneck would mix features together again. An overcomplete, sparse code gives each feature its own latent, which is the point.

Interleaving with IN.2: you find an SAE feature that seems to mean "French text". What is the strongest evidence it means that to the model?

  1. Clamping it high makes the model write French, and zeroing it disrupts French-specific behaviour
  2. Its top activating examples are mostly French
  3. A linear probe can predict it
  4. It has a large decoder norm
Top examples are a good start, but like a probe they are correlational. Interventions (steering and ablation) show the feature is actually used.

As an SAE's dictionary grows from 4,096 to 131,072 latents, a single "punctuation" feature is replaced by separate features for commas, periods and question marks. What is this called?

  1. Dead latents
  2. Dark matter
  3. Superposition
  4. Feature splitting
Bigger dictionaries carve concepts more finely. That's why "the" set of features isn't well defined: it depends on the SAE's size.

An SAE has $\lambda$ set so high that it reconstructs activations poorly. Swapping its reconstruction into the LLM will most likely…

  1. Improve the LLM's loss, since the features are cleaner
  2. Leave the LLM's loss unchanged
  3. Make the LLM's next-token loss worse, because information the model used has been dropped
  4. Delete the SAE's dead latents
Whatever the SAE fails to reconstruct is lost to the later layers. Measuring the loss increase from substituting $\hat{x}$ is one standard way to evaluate an SAE.

Key takeaways

  • An SAE is dictionary learning on activations: $f = \mathrm{ReLU}(W_{\text{enc}}(x - b_{\text{dec}}) + b_{\text{enc}})$, $\hat{x} = W_{\text{dec}} f + b_{\text{dec}}$, loss $\lVert x - \hat{x}\rVert^2 + \lambda \sum |f_i|$, with many more latents than dimensions.
  • At scale: Claude 3 Sonnet (up to ~34M features, Golden Gate Claude), GPT-4 (16M-latent TopK SAE), open Gemma Scope SAEs (JumpReLU) and Gemma Scope 2.
  • Transcoders and attribution graphs connect features across layers into circuits (Anthropic, 2025), checked with interventions.
  • Limits: reconstruction error (dark matter), feature splitting and absorption, dead latents, and no ground truth for evaluation; for some tasks simple probes do better.
