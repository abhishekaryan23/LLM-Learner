Softmax

Lesson 2 of Neural nets → language

Every time an LLM picks its next token, its last step is a softmax. It turns a list of raw scores into probabilities that are positive and add up to exactly 1. Attention uses the same function to turn scores into weights. Two lines of math, and a few traps worth knowing.

By the end you can

  • Compute a softmax by hand, including the stable "subtract the max" version.
  • Explain why adding a constant to every logit changes nothing, and what temperature does.
  • Connect softmax to the cross-entropy training loss and its simple gradient, $p - y$.
Builds on: MLPs (the network's last layer produces the scores), Probability & expectation (what a distribution is) and Entropy, cross-entropy & KL (the loss that softmax feeds). You'll meet it again in M1.1 Attention, where it turns scores into weights.

  2. more random and creative
  3. shorter
  4. no different; temperature only affects speed
Low temperature sharpens the distribution toward the highest-scoring token. High temperature flattens it, so less likely tokens get picked more often.

Scores are not probabilities

An LLM's final layer outputs one number per entry in its vocabulary: 50,257 numbers for GPT-2, 128,256 for Llama 3. These are logits: raw, unbounded scores where higher means "more likely next". But they can be negative and don't add up to anything in particular, so we can't sample from them directly. We need a function that makes every value positive, makes them sum to 1, and keeps the order (a higher score should still mean a higher probability). Softmax does all three:

$$\mathrm{softmax}(z)_i = \frac{e^{z_i}}{\sum_{j=1}^{V} e^{z_j}}$$

$z$ is the vector of logits, $z_i$ the logit of token $i$, and $V$ the vocabulary size. The exponential $e^{z_i}$ makes each value positive (and turns differences in score into ratios of probability). Dividing by the sum over all $V$ tokens, the normaliser, makes them add up to 1.

The name says what it is: a soft version of "argmax". A hard argmax would put probability 1 on the top token and 0 everywhere else. Softmax leans toward the top token, but keeps some probability for the rest, and it is smooth, so gradients can flow through it.

Explain like I'm 5

Four kids share one pie. Each one cheers for it, and the pie is cut according to how loud they cheer.

The loudest cheerer gets the biggest slice, and a little extra loudness wins a lot more pie. A quiet kid still gets a small slice, never a negative one. And however loud or quiet the whole group is, the whole pie gets shared out, no more and no less.

Where it breaks: logits can be negative, which a cheer can't. Only how much louder one kid is than the others matters, not how loud they all are.

Only the differences matter

Add the same constant $c$ to every logit:

$$\frac{e^{z_i + c}}{\sum_j e^{z_j + c}} = \frac{e^{c}\,e^{z_i}}{e^{c}\sum_j e^{z_j}} = \frac{e^{z_i}}{\sum_j e^{z_j}}$$

The $e^c$ cancels, so the output is identical. Softmax only sees how far apart the logits are, never their absolute level.

That property is a lifesaver in code. In 32-bit floats, $e^{z}$ overflows to infinity once $z$ passes about 88.7; in 16-bit floats (fp16), already at about 11.1. Logits of that size are routine. So every real implementation subtracts the largest logit first:

$$\mathrm{softmax}(z) = \mathrm{softmax}(z - \max_j z_j)$$

Now the biggest exponent is $e^0 = 1$ and nothing can overflow. The same trick, called log-sum-exp, computes $\log \mathrm{softmax}$ stably, which is why frameworks such as PyTorch take raw logits in their cross-entropy loss instead of probabilities.

Worked example

Logits $z = [2,\ 1,\ 0]$.

  1. Exponentiate: $e^2 \approx 7.389$, $e^1 \approx 2.718$, $e^0 = 1$
  2. Sum: $7.389 + 2.718 + 1 = 11.107$
  3. Divide: $[7.389,\ 2.718,\ 1] / 11.107 \approx [0.665,\ 0.245,\ 0.090]$, which sums to 1 ✓

Temperature: a preview

Divide the logits by a positive number $T$, the temperature, before the softmax:

$$p_i = \frac{e^{z_i / T}}{\sum_j e^{z_j / T}}$$
  • $T = 1$: the model's own distribution.
  • $T < 1$: gaps grow, the distribution gets sharper. As $T \to 0$ it approaches a one-hot on the top token (greedy decoding). For $z = [2, 1, 0]$, $T = 0.5$ gives $[0.87,\ 0.12,\ 0.02]$.
  • $T > 1$: gaps shrink, the distribution gets flatter. As $T \to \infty$ it approaches uniform. $T = 2$ gives $[0.51,\ 0.31,\ 0.19]$.

Temperature never changes the order of the tokens, only how strongly the top one is preferred. You'll use it, along with top-k and top-p, when we look at sampling in KV cache & sampling.

Softmax meets cross-entropy

During training, the correct next token is known. The loss is the cross-entropy from P1.6: minus the log of the probability the model gave to the right answer.

$$\mathcal{L} = -\log p_{\text{target}}$$

In the animation, if the true next word was "mat" ($p = 0.73$), the loss is $-\ln 0.73 \approx 0.32$. If it was "floor" ($p \approx 0.16$), the loss is about $1.8$: a bigger surprise costs more.

Softmax and cross-entropy fit together beautifully. The gradient of the loss with respect to each logit is just

$$\frac{\partial \mathcal{L}}{\partial z_i} = p_i - y_i$$

where $y$ is the one-hot vector of the true token (1 for the target, 0 elsewhere). So with target "floor", the gradient is $[0.73,\ 0.16 - 1,\ 0.10,\ 0.01] = [0.73,\ -0.84,\ 0.10,\ 0.01]$. Gradient descent (P2.2) subtracts it, which pushes the "floor" logit up and every other logit down, each in proportion to how much probability it wrongly took.

A two-way softmax is the familiar sigmoid: $\mathrm{softmax}([z, 0])_1 = \frac{e^z}{e^z + 1} = \frac{1}{1 + e^{-z}} = \sigma(z)$.

Why this matters for LLMs: softmax shows up at every key point. It turns attention scores into weights in every head of every layer (M1.1), and turns the final logits into the next-token distribution that both the training loss and sampling use (M2.2, M1.5). Because $e^z$ is so sensitive to large values, softmax is usually computed in 32-bit precision even when the rest of the model runs in 16-bit (M2.5). And "soft" targets from a teacher's temperature-raised softmax are the core of distillation (Hinton et al., 2015; M5.2).

Model answer: Softmax exponentiates each score and divides by the sum, giving positive numbers that add to 1, with bigger scores getting exponentially more probability. Only differences between scores matter, so subtracting the max gives the same answer while keeping every exponent at most $e^0 = 1$, which prevents overflow.
Check yourself

Which logit vector gives the same softmax output as $[1, 2, 3]$?

  1. $[2, 4, 6]$
  2. $[-2, -1, 0]$
  3. $[3, 2, 1]$
  4. $[0.1, 0.2, 0.3]$
$[-2, -1, 0]$ is $[1, 2, 3]$ minus 3, so all differences are the same. Doubling (A) is like temperature 0.5 and sharpens the result; dividing by 10 (D) flattens it; (C) reverses the order.

Why do implementations compute $\mathrm{softmax}(z - \max z)$?

  1. It makes the probabilities sharper
  2. It makes them sum to 1
  3. It makes training converge faster
  4. It gives the identical result while keeping $e^z \le 1$, so large logits can't overflow
Shifting all logits by a constant cancels in the ratio. After the shift the largest exponent is $e^0 = 1$; without it, $e^{z}$ overflows fp32 above $z \approx 88.7$ and fp16 above $z \approx 11.1$.

As the temperature $T$ goes toward 0, softmax$(z/T)$ approaches…

  1. a one-hot vector on the largest logit
  2. the uniform distribution
  3. the raw logits
  4. all zeros
Dividing by a tiny $T$ blows up every gap, so the top token takes essentially all the probability. That's greedy decoding. Large $T$ goes the other way, toward uniform.

With softmax followed by cross-entropy loss (P1.6), the gradient of the loss with respect to logit $z_i$ is…

  1. $-\log p_i$
  2. $p_i(1 - p_i)$
  3. $p_i - y_i$, where $y$ is the one-hot target
  4. always zero for the correct token
The predicted probability minus the target. It's negative for the correct token (so gradient descent raises that logit) and positive for the others, and it vanishes only when the prediction exactly matches the target.

Key takeaways

  • $\mathrm{softmax}(z)_i = e^{z_i} / \sum_j e^{z_j}$: positive outputs that sum to 1, with the order kept.
  • Only differences between logits matter. Subtract the max before exponentiating to avoid overflow.
  • Temperature divides the logits: $T < 1$ sharpens, $T > 1$ flattens, $T \to 0$ is greedy.
  • Training uses $-\log p_{\text{target}}$, whose gradient with respect to the logits is simply $p - y$.
