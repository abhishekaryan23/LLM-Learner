Backpropagation

Lesson 3 of Machine-learning basics

Gradient descent needs the slope of the loss for every parameter: billions of them in an LLM. Backpropagation gets them all in a single backward sweep through the network, and that sweep costs only about twice as much as the forward pass.

By the end you can

  • Write a small model as a computational graph and run its forward pass.
  • Run the backward pass by hand: upstream gradient × local derivative at every node, adding up where a value branches.
  • Explain why backprop costs about as much as a couple of forward passes, not one pass per parameter.

  3. 0.07

$\frac{\partial f}{\partial a} = b = 4$, so $f$ moves by $4 \times 0.01 = 0.04$. "The derivative of a product with respect to one input is the other input" is one of the local rules backprop uses at every node.

The problem: one slope per parameter

Training needs $\frac{\partial L}{\partial \theta_i}$, the slope of the loss with respect to each parameter $\theta_i$. The obvious way is to nudge each parameter by a tiny $\varepsilon$ and measure how the loss moves:

$$\frac{\partial L}{\partial \theta_i} \approx \frac{L(\theta_1, \dots, \theta_i + \varepsilon, \dots) - L(\theta)}{\varepsilon}$$

That works, and it's a great way to check gradients, but it costs one extra forward pass per parameter. For a 7-billion-parameter model that's 7 billion forward passes for one step. Hopeless.

Backpropagation computes the exact gradient for every parameter with one forward pass and one backward pass. It's a special case of reverse-mode automatic differentiation (described by Linnainmaa in 1970) and was popularised for neural networks by Rumelhart, Hinton & Williams (1986), "Learning representations by back-propagating errors".

Step 1: the model as a graph

Any model, from a line to a transformer, is built from simple operations: multiply, add, relu, square, exp. Draw each operation as a box and connect the boxes by the values that flow between them. That's a computational graph. Our example is a tiny two-layer network with one hidden unit:

$$z = w\,x, \qquad h = \text{relu}(z), \qquad \hat y = v\,h, \qquad L = (\hat y - y)^2$$

$x$ is the input, $y$ the target, $w$ and $v$ the two weights we want to train, and $\text{relu}(z) = \max(0, z)$.

Step 2: forward, then backward

The forward pass computes every box in order, from inputs to loss, and stores each intermediate value. The backward pass then walks the graph in reverse. At each box it applies the chain rule (P1.3): if a value $u$ feeds a box whose output is $n$, then

$$\frac{\partial L}{\partial u} = \frac{\partial L}{\partial n}\cdot\frac{\partial n}{\partial u}$$

$\frac{\partial L}{\partial n}$ is the upstream gradient, already computed one box closer to the loss. $\frac{\partial n}{\partial u}$ is the box's local derivative, which depends only on that one simple operation and the values stored in the forward pass. Each box needs only a handful of local rules:

  • add $n = a + b$: local derivative 1 for both inputs (the gradient is copied).
  • multiply $n = a\,b$: $\frac{\partial n}{\partial a} = b$ and $\frac{\partial n}{\partial b} = a$ (each input gets the other one).
  • relu: 1 if the input was positive, 0 otherwise (the gradient passes or is blocked).
  • squared error $(\hat y - y)^2$: $2(\hat y - y)$ with respect to $\hat y$.
Explain like I'm 5

A line of kids passes buckets of water to fill a pool at the end. The pool comes out too empty.

The kid at the pool says to the kid before them, "we were short by this much". That kid works out their share of the problem, adjusts their bucket, and passes a message back to the kid before them. The message travels all the way back down the line, so every kid learns how to change, from just one trip back.

Where the analogy breaks: real backprop doesn't change anything on the way back. It only computes every gradient; the optimizer then updates all the weights at once.

Worked example (the animation, in writing)

$x = 1.5$, $w = 2$, $v = 0.5$, $y = 2.5$.

  1. Forward: $z = 3$, $h = 3$, $\hat y = 1.5$, $L = (1.5 - 2.5)^2 = 1$.
  2. $\frac{\partial L}{\partial \hat y} = 2(\hat y - y) = -2$.
  3. Through $\hat y = v\,h$: $\frac{\partial L}{\partial v} = -2 \times h = -6$ and $\frac{\partial L}{\partial h} = -2 \times v = -1$.
  4. Through relu (input $3 > 0$): $\frac{\partial L}{\partial z} = -1 \times 1 = -1$.
  5. Through $z = w\,x$: $\frac{\partial L}{\partial w} = -1 \times x = -1.5$.
  6. Both weight gradients are negative, so gradient descent raises both weights. With $\eta = 0.02$: $w = 2.03$, $v = 0.62$, and the loss drops to about $0.37$.

Branches: gradients add up

Real graphs aren't chains. A value often feeds several boxes: a residual connection, a weight reused at every position, an embedding looked up many times in a batch. If $u$ feeds boxes $n_1, \dots, n_k$, it affects the loss along every one of those paths, and the multivariable chain rule adds the contributions:

$$\frac{\partial L}{\partial u} = \sum_{j=1}^{k} \frac{\partial L}{\partial n_j}\cdot\frac{\partial n_j}{\partial u}$$

This is why frameworks accumulate gradients: in PyTorch, .grad is added to, not overwritten, which is also why training loops call zero_grad() before every backward pass (P4.1, P4.2).

Why it's so cheap

The forward pass visits each box once. The backward pass visits each box once more and does a small, fixed amount of work there: a multiply or two using values already stored. So the whole gradient, for all parameters, costs a small constant multiple of one forward pass, however many parameters there are. Compare that with one forward pass per parameter for nudging.

For networks dominated by matrix multiplications, the backward pass needs two matrix multiplies for every one in the forward pass (one for the gradient with respect to the weights, one for the gradient with respect to the inputs), so it costs about 2× the forward pass. That gives the well-known estimate of about $6N$ floating-point operations per training token for a model with $N$ parameters: $2N$ forward plus $4N$ backward (Kaplan et al., 2020).

The price is memory: every intermediate value from the forward pass must be kept until the backward pass uses it. For large models these stored activations can take more memory than the weights themselves, which is why tricks like activation checkpointing (recompute some values instead of storing them) exist (M2.5).

Two consequences you'll meet again: if a relu's input is negative its local derivative is 0 and no gradient flows through it; and multiplying many local derivatives smaller than 1 across many layers can shrink gradients toward zero (vanishing gradients), which residual connections and careful normalisation help prevent.

Why this matters for LLMs: you will never write a backward pass by hand. PyTorch's autograd (P4.1) records the graph as your code runs and replays it backwards when you call loss.backward(). But backprop explains a lot of practice: why training needs far more memory than inference (stored activations, plus gradients), why training a model costs about 3× the compute of running it on the same tokens, and why gradient clipping, residual connections and normalisation layers exist (keeping gradients well-behaved through dozens of layers).
Explain it back · in two or three sentences

Why does backpropagation get every parameter's gradient for about the cost of a couple of forward passes, when nudging needs one forward pass per parameter?

Model answer: The forward pass stores every intermediate value. The backward pass then visits each operation once, in reverse, multiplying the upstream gradient by that operation's local derivative (the chain rule), so all the shared work along the way is reused instead of recomputed for each parameter. The total is a small constant multiple of the forward cost, independent of the number of parameters.

A box computes $n = a\cdot b$ with $a = 2$, $b = 5$. The upstream gradient is $\frac{\partial L}{\partial n} = 3$. What is $\frac{\partial L}{\partial a}$?

  1. 15
  2. 6
  3. 10
  4. 3
Upstream × local: $3 \times \frac{\partial n}{\partial a} = 3 \times b = 15$. Using $a$ instead of $b$ gives the wrong answer 6.

A value $u$ feeds two boxes. Backprop gets a contribution of $2$ through the first and $-5$ through the second. What is $\frac{\partial L}{\partial u}$?

  1. $-10$, the product
  2. $2$, from the first path only
  3. $-3$, the sum
  4. $-5$, the larger one
When a value is used in several places, the gradients from all paths add (multivariable chain rule).

For a large network made mostly of matrix multiplications, how does the backward pass's cost compare with the forward pass's?

  1. About the same as one forward pass per parameter
  2. Roughly twice the forward pass, regardless of the number of parameters
  3. Free: the gradients come out of the forward pass
  4. About the square of the forward cost
Each forward matmul needs two in the backward pass (gradients for the weights and for the inputs). Hence the "6N FLOPs per token" rule for training: 2N forward + 4N backward.

Backprop gives $\frac{\partial L}{\partial w} = -1.5$. With learning rate $\eta = 0.1$, what does one step of gradient descent (P2.2) do to $w$?

  1. Decreases it by 0.15
  2. Sets it to −1.5
  3. Decreases it by 1.5
  4. Increases it by 0.15
$w \leftarrow w - \eta\,\frac{\partial L}{\partial w} = w - 0.1 \times (-1.5) = w + 0.15$. A negative gradient means "increasing $w$ lowers the loss". Backprop computes the gradient; the optimizer uses it.

Key takeaways

  • A model is a computational graph of simple operations.
  • Forward computes and stores every value; backward walks the graph in reverse.
  • At each node: gradient = upstream gradient × local derivative (the chain rule).
  • Where a value feeds several nodes, its gradients add up.
  • All gradients cost about 2× a forward pass in compute, plus memory for the stored activations.
