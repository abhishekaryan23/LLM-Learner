Native multimodal & any-to-any models

Lesson 2 of Multimodal models

The models in MM.1 can look at a picture but can only answer in words, and they learned language long before they saw an image. The next step is a single model that is trained on text, images and sound from the start, and can also produce them. This lesson shows the two main ways to build one, and what it costs.

By the end you can

  • Distinguish late fusion (an adapter on a finished text LLM) from early fusion (one model trained on mixed tokens from the start).
  • Explain how discrete image tokens (Chameleon) and an in-model diffusion loss (Transfusion) let one transformer generate images, not just read them.
  • Weigh any-to-any trade-offs: token budgets, latency, and quality against specialist models.

A LLaVA-style model (vision encoder → projector → text LLM) is asked to “draw a cat”. What can it output?

  1. A picture of a cat, through its projector run in reverse
  2. Only text, for example a description or SVG code, because its output layer scores text tokens only
  3. Visual tokens that any screen can display
  4. Nothing; it can't run without an image input
Late-fusion models read images, but their output head only covers the text vocabulary. To generate images, a model needs image tokens in its output vocabulary or an image decoder of some kind.

An image tokenizer turns a 512×512 image into 1,024 discrete codes. To generate one image token by token, an autoregressive model needs about…

  1. 1 forward pass
  2. 32 forward passes
  3. 1,024 forward passes, one per code
  4. 262,144 forward passes, one per pixel
Like text, the codes come out one at a time, so one image costs about as many decoding steps as a 1,024-token answer. That's a big reason some unified models generate images with diffusion instead.

Late fusion vs early fusion

The recipe in MM.1 is late fusion: pretrain a text LLM and a vision encoder separately, then connect them. It is cheap and reuses the best text model you have, but it has three limits. Vision is input only; the model can't produce an image or a voice. Language was learned first and images were added later, from far less data. And for speech you need a pipeline: speech recognition, then the LLM, then text-to-speech, which adds delay and loses tone of voice.

Early fusion puts every modality into one token sequence from the start of pretraining, and lets the model write those tokens as well as read them. Two 2023–24 launches made “natively multimodal” the goal for frontier labs:

  • Gemini 1.0 (Gemini Team, Google, December 2023) was described as trained jointly on text, images, audio and video, accepting them interleaved, and its report says it can output images using discrete image tokens. The report gives few architectural details.
  • GPT-4o (OpenAI, May 2024) was announced as “a single new model end-to-end across text, vision, and audio”. OpenAI's earlier Voice Mode chained three models, with average latencies of 2.8 s (GPT-3.5) and 5.4 s (GPT-4); GPT-4o was said to answer speech in as little as 232 ms, 320 ms on average. Its architecture has not been published.

A warning about words: some papers call LLaVA-style models “early fusion” because visual tokens enter at the first layer, in contrast to Flamingo's cross-attention deep inside the network. Here we follow the Chameleon paper's usage: early fusion means one shared token space, trained together from the beginning.   2. A vision encoder is attached to a finished text LLM with a projector
  3. Two separate models vote on the answer
Option 2 is late fusion (MM.1). Early fusion trains one model on mixed-modality tokens from the beginning, so it can read and write every modality it was trained on.

Images as tokens: Chameleon

The cleanest early-fusion design treats an image exactly like text. Chameleon (Chameleon Team, Meta, 2024) uses an image tokenizer, a vector-quantised autoencoder in the style of those in G1.6. It turns a 512×512 image into a 32×32 grid of codes: each 16×16-pixel region is replaced by the index of the nearest of 8,192 learned codebook vectors. Those 1,024 indices become ordinary token IDs in a shared vocabulary of 65,536 entries, next to the text tokens.

From there it is “just” language modelling. One transformer (7B and 34B versions) is trained from scratch with the next-token loss on text-only data, image–text pairs and interleaved documents. Because image codes are in the output vocabulary, the same model can answer a question about a picture or write a picture in the middle of a story. The paper reports two practical lessons:

  • Mixing modalities made training unstable at scale; the authors needed architectural changes such as normalising queries and keys inside attention to keep it from diverging.
  • The tokenizer sets a ceiling. Discrete codes lose fine detail, and the authors note their tokenizer struggles to reconstruct images with a lot of text, which hurts OCR-heavy tasks.

Worked example: the token bill

An illustrated story with 4 images and 800 words, at about 1.3 text tokens per word:

  1. Image tokens: $4 \times 1{,}024 = 4{,}096$.
  2. Text tokens: $800 \times 1.3 = 1{,}040$.
  3. Total: $5{,}136$, of which images are $4{,}096 / 5{,}136 \approx 80\%$.
  4. Writing it means 4,096 sequential decoding steps for the pictures alone.

Why can Chameleon generate images while LLaVA can't?

  1. Chameleon has a bigger vision encoder
  2. Chameleon uses cross-attention instead of a projector
  3. Its output vocabulary includes the 8,192 image codes, so it can predict them like words and decode them back to pixels
Generation needs image tokens on the output side. With codes in the vocabulary, “draw a cat” is next-token prediction followed by the tokenizer's decoder.

Next-token prediction plus diffusion: Transfusion

Discrete codes have two costs: quantising throws away detail, and generating thousands of codes one by one is slow. Meanwhile, diffusion models (G1.3, G1.4) make the best images. Transfusion (Zhou et al., 2024, Meta) asks: why not train one transformer to do both?

  • Text stays discrete and gets the usual next-token loss.
  • Images are encoded by a VAE into continuous latent patches, as in latent diffusion. During training the patches are noised, and the same transformer predicts the noise: a diffusion loss.
$$\mathcal{L} = \mathcal{L}_{\text{LM}} + \lambda\,\mathcal{L}_{\text{diffusion}}$$

$\mathcal{L}_{\text{LM}}$ is cross-entropy on the text tokens, $\mathcal{L}_{\text{diffusion}}$ is the mean squared error between the true and predicted noise on the image patches, and $\lambda$ is a weight that balances the two. One set of weights, one forward pass per training sequence, two losses.

The attention mask is mixed too. Across the sequence it is causal, as in any LLM (M1.4), but inside an image all patches see each other, because an image has no natural left-to-right order and diffusion denoises all patches together. At generation time the model writes text normally; when it emits a begin-image token it switches mode, starts from pure-noise patches and denoises them over a fixed number of steps, each a parallel pass over the whole image, then returns to text.

The authors scaled the recipe to 7B parameters and 2T multimodal tokens and reported text and image generation on par with similar-scale language and diffusion models. In their comparisons it also scaled better than a Chameleon-style discrete-token baseline. Other teams explored neighbouring designs: Show-o (Xie et al., 2024) uses discrete diffusion for images; Janus (DeepSeek, 2024) uses separate visual encoders for understanding and for generation inside one model. As of 2026 there is no single winning recipe for unified understanding-and-generation models, and the leading closed models disclose little about theirs.

In Transfusion's attention mask, which pairs of positions can attend to each other?

  1. Every position sees every other position, everywhere
  2. Each position sees earlier positions, and patches of the same image also see each other in both directions
  3. Text tokens can't see image patches at all
The mask is causal overall, so text after an image can read it, but within an image attention is bidirectional, which suits denoising all patches together.

Speech in, speech out, and the any-to-any bill

Sound fits the same mould. A neural audio codec (A1.3) turns a waveform into a few streams of discrete codes, and a decoder turns codes back into audio. Put those codes in the sequence and a model can listen and talk without a text detour, so tone, pauses and laughter can survive. Kyutai's Moshi (Défossez et al., 2024) is a well-documented example: its Mimi codec produces 12.5 frames per second with 8 codebooks, and the model listens and speaks at the same time (A1.6).

The token bill is real. One minute of speech is $60 \times 12.5 \times 8 = 6{,}000$ codes if you flatten every codebook into the sequence, against roughly 200 text tokens for the same 150 spoken words. Moshi avoids flattening: a small “depth” transformer predicts the 8 codes of a frame, so the main model takes just one step per frame, 750 steps a minute. Any-to-any models trade along several axes:

  • Token budget. Images and audio are token-hungry, so context length, KV cache memory and compute all grow (M1.5).
  • Quality vs specialists. One network shares its capacity and training data across modalities. Dedicated image or speech models have often led on their single task, though the gap has been narrowing, and results vary by task.
  • Training mix. The data balance between modalities matters, and modalities can interfere with each other during training; Chameleon's instability is one example.
  • The payoff. One shared context: edit a picture by talking about it, read a chart and redraw it, answer in a voice that matches the question's tone.

As of 2026, frontier assistants generally accept text, images and audio (often video too), and many also generate images and speech. How much of that runs inside one network and how much is routed to specialist models is usually not disclosed, so treat “natively multimodal” in a product announcement as a claim about training, not a full architecture description.

Explain like I'm 5

Imagine a writer who only knows words. To tell them about a photo, a helper whispers what's in it. The writer can answer, but can't draw anything back. That's late fusion.

Now imagine a kid who grew up with picture books, songs and stories all mixed together. When you ask something, they can answer with words, a drawing or a song, because for them it was always one language. That's early fusion.

Where it breaks: the kid doesn't really draw “one crayon stroke at a time from left to right”, but a token model does build an image one code at a time, which is why it's slow.

Why this matters in practice: pick the architecture for the job. If your product only needs to understand images (search, captioning, document Q&A), a late-fusion model reuses a strong text LLM cheaply. For real-time voice, native speech-to-speech avoids the latency and lost tone of a three-model pipeline. For editing images in conversation, a unified model keeps the whole exchange in one context. And whichever you use, count the tokens: an image or a minute of audio can cost more than everything else in the prompt.

Explain it back · in two or three sentences

What does “natively multimodal” add over an MM.1-style model, and what are two ways to let one model generate images?

Model answer: A natively multimodal (early-fusion) model is trained on text, image and audio tokens in one sequence from the start, so it can produce those modalities as well as read them, instead of bolting an encoder onto a finished text LLM. One way to generate images is to make them discrete tokens in the shared vocabulary and predict them one by one (Chameleon); another is to keep images as continuous latent patches and train the same transformer with a diffusion loss on them alongside the next-token loss on text (Transfusion).
Check yourself

Which model is an example of early fusion with discrete image tokens?

  1. LLaVA
  2. BLIP-2
  3. Flamingo
  4. Chameleon
LLaVA, BLIP-2 and Flamingo all connect a vision encoder to a separately pretrained language model (MM.1). Chameleon trains one model from scratch on a shared vocabulary of text and image codes.

Recall the KV cache (M1.5). Chameleon generates a 1,024-code image after a 50-token prompt. With a KV cache, roughly how many sequential forward steps does the image take?

  1. 1, because the cache stores the whole image
  2. About 1,024, one per code; the cache only stops each step from recomputing the earlier tokens
  3. About 1,074², because attention is quadratic
  4. 50, one per prompt token
A KV cache makes each step cheap but doesn't remove the steps: autoregressive generation still emits one token per forward pass.

What does Transfusion's diffusion loss train the transformer to do on image positions?

  1. Predict the noise that was added to continuous latent image patches
  2. Predict the next image code from an 8,192-entry codebook
  3. Classify the image into one of 1,000 classes
  4. Reconstruct the text caption
Image patches stay continuous (VAE latents). They're noised in training and the model learns to predict the noise, exactly the diffusion objective of G1.3, while text keeps its next-token loss.

A team builds a voice assistant as speech recognition → text LLM → text-to-speech. What do they lose compared with a native speech-to-speech model?

  1. The ability to answer questions at all
  2. Nothing; pipelines and native models behave identically
  3. Latency from chaining three models, and paralinguistic information such as tone and emotion that the text step drops
  4. The ability to use a large language model
The text bottleneck discards how something was said, and each stage adds delay. OpenAI cited exactly this when it replaced its three-model Voice Mode with GPT-4o.

Key takeaways

  • Late fusion adds vision to a finished text LLM (input only); early fusion trains one model on mixed-modality tokens from the start and can output them too.
  • Chameleon: a 512×512 image → 1,024 discrete codes in a shared 65,536-token vocabulary; generation is next-token prediction, one code at a time.
  • Transfusion: one transformer, next-token loss on text plus diffusion loss on continuous image patches, bidirectional attention inside each image.
  • Codec tokens bring speech in and out without a text detour, but audio and images are token-hungry.
  • Any-to-any trades token budget, training stability and per-task quality for one shared context. Frontier labs disclose little, so hedge architecture claims.
