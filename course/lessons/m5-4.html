FlashAttention & paged attention

Lesson 4 of Optimization

On a modern GPU, attention is slow less because of the arithmetic and more because of moving data. Two ideas fixed most of that. FlashAttention computes exactly the same attention without ever storing the $n \times n$ matrix. PagedAttention stores the KV cache in small blocks, the way an operating system stores memory in pages.

By the end you can

  • Explain why standard attention is limited by memory bandwidth, using the HBM vs SRAM gap.
  • Merge two blocks of a softmax with the online-softmax update (running max and sum), by hand.
  • Explain how PagedAttention's block tables cut KV-cache waste and let requests share memory.
Before you start: this lesson builds on Attention (the $n \times n$ score matrix and the softmax over each row) and KV cache & sampling (why generation stores every token's keys and values). It helps to remember the "subtract the max" trick for a stable softmax.
Warm-up · guess before you learn

A guess now makes the answer stick later.

For long sequences on a GPU, what mostly limits the speed of plain (unfused) attention?

  1. The number of multiply-adds in $QK^\top$
  2. Reading and writing large $n \times n$ matrices to and from GPU main memory
  3. The CPU preparing the inputs
  4. The softmax needing a square root
GPUs can do arithmetic far faster than they can move bytes from main memory. Writing an $n \times n$ matrix out and reading it back, twice, dominates the time.

FlashAttention makes attention faster by…

  1. approximating attention with a low-rank matrix
  2. only attending to nearby tokens
  3. computing exactly the same result while moving far less data
  4. storing the attention weights in 4-bit
FlashAttention is exact. It reorganises the computation into tiles that fit in fast on-chip memory, so the big matrices never travel to main memory.

Two kinds of GPU memory

A GPU has a memory hierarchy. The FlashAttention paper uses an NVIDIA A100 as its example:

  • HBM (high-bandwidth memory) is the GPU's main memory: 40–80 GB, read and written at about 1.5–2.0 TB/s. Your weights, activations and KV cache live here.
  • SRAM is on the chip itself: 192 KB next to each of the 108 streaming multiprocessors, about 20 MB in total, with an estimated bandwidth of about 19 TB/s.

Newer GPUs move the numbers but keep the shape: an H100 has 80 GB of HBM3 at about 3.35 TB/s, and still only a few hundred KB of SRAM per multiprocessor. Meanwhile the A100 does about 312 trillion 16-bit floating-point operations per second (FLOP/s). Divide compute by bandwidth: $312 \times 10^{12} / 2 \times 10^{12} \approx 156$. An operation must do about 156 FLOPs for every byte it moves from HBM, or the arithmetic units sit idle waiting for data. Such an operation is called memory-bound.

FLOPs per byte moved is called arithmetic intensity. Matrix multiplies on big matrices have plenty of it. Softmax, masking and other element-wise steps do a few FLOPs per number, so they are memory-bound.

Where standard attention spends its time

Recall from M1.1: $O = \mathrm{softmax}(QK^\top/\sqrt{d_k})\,V$. A straightforward implementation runs it as separate GPU kernels (programs), each reading its inputs from HBM and writing its result back:

  1. Read $Q$, $K$; compute $S = QK^\top/\sqrt{d_k}$; write $S$ ($n \times n$) to HBM.
  2. Read $S$; compute $P = \mathrm{softmax}(S)$ row by row; write $P$ ($n \times n$) to HBM.
  3. Read $P$ and $V$; compute $O = PV$; write $O$ ($n \times d$).

The $n \times n$ matrices are huge. At $n = 8{,}192$ tokens in 16-bit, $S$ alone is $8192^2 \times 2$ bytes $= 128$ MiB per head. With 32 heads that's 4 GiB per layer for one sequence, written and read back twice. Memory use grows as $O(n^2)$, and so does the traffic.

The trick that makes tiling possible: online softmax

Tiling a matrix multiply is easy. The obstacle is the softmax in the middle: to normalise row $i$ you seem to need the whole row first, its max (for stability) and its sum. FlashAttention gets around this with an online softmax (Milakov & Gimelshein, 2018; used for memory-efficient attention by Rabe & Staats, 2021). It keeps three running quantities per query row:

  • $m$: the largest score seen so far,
  • $\ell$: the sum of $e^{s_j - m}$ over the keys seen so far,
  • $a$: the matching weighted sum of values, $\sum_j e^{s_j - m}\,v_j$ (the output before dividing by $\ell$).

When a new block $B$ of keys arrives with scores $s_j$:

$$m' = \max\!\Big(m,\ \max_{j \in B} s_j\Big)$$ $$\ell' = e^{\,m - m'}\,\ell \;+\; \sum_{j \in B} e^{\,s_j - m'} \qquad a' = e^{\,m - m'}\,a \;+\; \sum_{j \in B} e^{\,s_j - m'}\,v_j$$

After the last block, the output is $o = a / \ell$. The factor $e^{m - m'}$ is a correction: the old terms were computed as $e^{s_j - m}$, and multiplying by $e^{m - m'}$ turns each into $e^{s_j - m'}$, as if the new max had been known all along. It is at most 1, so nothing overflows. Because every step is an exact rewrite, the final answer is exactly the ordinary softmax, up to floating-point rounding.

Worked example: merging two blocks

One query, four keys in two blocks of two. Scores $s = [2, 1 \,|\, 3, 0]$, values (scalars, to keep it short) $v = [1, 2 \,|\, 3, 4]$.

  1. Block 1: $m = 2$. $\ell = e^{0} + e^{-1} = 1 + 0.368 = 1.368$. $a = 1 \cdot 1 + 0.368 \cdot 2 = 1.736$.
  2. Block 2 raises the max: $m' = \max(2, 3) = 3$. Correction $e^{2-3} = 0.368$.
  3. $\ell' = 0.368 \times 1.368 + e^{0} + e^{-3} = 0.503 + 1 + 0.050 = 1.553$.
  4. $a' = 0.368 \times 1.736 + 1 \cdot 3 + 0.050 \cdot 4 = 0.639 + 3 + 0.199 = 3.838$.
  5. Output: $o = 3.838 / 1.553 = 2.471$. Check with an ordinary softmax over all four scores: weights $[0.237, 0.087, 0.644, 0.032]$, and $0.237 + 0.174 + 1.932 + 0.128 = 2.471$ ✓

FlashAttention: tiles, a fused kernel and recomputation

FlashAttention (Dao et al., 2022, "FlashAttention: Fast and Memory-Efficient Exact Attention with IO-Awareness") puts the pieces together in a single fused kernel:

  1. Split $Q$ into row blocks and $K$, $V$ into blocks small enough to fit in SRAM.
  2. For each $Q$ block: loop over the $K/V$ blocks. Score the tile in SRAM, apply the scale and causal mask, and update $m$, $\ell$ and the output accumulator with the online-softmax rule.
  3. After the last $K/V$ block, divide by $\ell$ and write that block of $O$ to HBM, plus the running max $m$ and sum $\ell$ of each row for the backward pass (FlashAttention-2 folds them into one log-sum-exp, $m + \log \ell$).

Training also needs the backward pass, which normally reads $P$ from memory. FlashAttention doesn't store $P$. Instead it recomputes the tiles of $S$ and $P$ from $Q$, $K$ and the saved log-sum-exp. That is extra arithmetic, but arithmetic is cheap and memory traffic is not.

The results, from the paper:

  • Memory: extra memory is $O(n)$ instead of $O(n^2)$. That is what made long context windows practical.
  • Traffic and time: on GPT-2 medium's attention (A100, forward + backward), HBM reads and writes fell from 40.3 GB to 4.4 GB and runtime from 41.7 ms to 7.3 ms, even though FlashAttention did more FLOPs (75.2 vs 66.6 GFLOPs) because of the recomputation.
  • End to end: about 3× faster GPT-2 training at sequence length 1K, and 15% faster BERT-large training than the MLPerf 1.1 record.

The paper also proves the I/O cost: about $\Theta(n^2 d^2 / M)$ HBM accesses, where $M$ is the SRAM size and $d$ the head dimension, compared with $\Theta(nd + n^2)$ for standard attention. With typical $d$ (64–128) and $M$ (around 100 KB), that is many times fewer.

Explain like I'm 5

Two kids have the same homework, and the answers are in books at a library far away.

The tired kid walks to the library for one book, reads it, walks back, writes a note on a giant sheet, carries the sheet back to the library… all day long. Most of the day is walking.

The happy kid brings a stack of books to the desk at once, works through them right there, keeps a tiny running tally on a sticky note, and walks back only once, with the finished answer. Same homework, same answer, far less walking.

The library is HBM, the desk is SRAM, the sticky note is $m$ and $\ell$. Where it breaks: on a GPU the cost is how many bytes per second fit through the link, not walking distance, and the happy kid still has to read every book at least once.

FlashAttention-2, -3 and what you actually use

FlashAttention-2 (Dao, 2023) kept the algorithm but split the work better across the GPU, including along the sequence, and cut non-matmul operations. It reported about 2× over the first version, reaching 50–73% of the A100's peak FLOP/s. FlashAttention-3 (Shah et al., 2024) targets H100 (Hopper) GPUs: it overlaps the softmax with the matrix multiplies using the chip's asynchronous hardware and adds FP8 support. The paper reports 1.5–2.0× over FlashAttention-2 in 16-bit. Exact speedups depend on the GPU, head dimension and sequence length, and newer versions keep appearing for newer hardware.

You rarely call these kernels yourself. PyTorch's scaled_dot_product_attention picks a FlashAttention-style kernel when the inputs allow it, and training frameworks and serving engines ship their own fused attention kernels built on the same ideas.

PagedAttention: the KV cache as virtual memory

FlashAttention fixes the cost of computing attention. Serving many users at once has a second memory problem: the KV cache (M1.5). It grows by one token per generated token, and it's big. For Llama 2 7B (32 layers, hidden size 4,096, 16-bit), keys plus values take $2 \times 32 \times 4096 \times 2$ bytes $= 0.5$ MiB per token, so one 4,096-token conversation needs 2 GiB.

A server doesn't know how long each answer will be. Earlier systems therefore reserved one contiguous chunk per request, sized for the maximum length. Most of it sat empty (internal fragmentation), and the leftover gaps between chunks were often too small to use (external fragmentation). Kwon et al. measured that only 20.4–38.2% of KV-cache memory held actual token states in the systems they studied.

PagedAttention (Kwon et al., 2023, "Efficient Memory Management for Large Language Model Serving with PagedAttention", the paper behind vLLM) borrows the operating system's idea of paging:

  • The cache is split into fixed-size blocks (vLLM's default is 16 tokens each).
  • Each request has a block table mapping its logical blocks to physical blocks anywhere in memory. The attention kernel follows the table to gather keys and values.
  • Blocks are allocated on demand, so the waste is at most one part-filled block per request. The paper reports under 4% waste.
  • Blocks can be shared. Parallel samples or beams of one prompt point at the same prompt blocks, with a reference count, and a shared block is copied only if one of them must change it (copy-on-write).

Less waste means more requests fit in memory at once, which means bigger batches and more tokens per second (M5.6 shows why). The vLLM paper reported 2–4× the throughput of earlier systems (FasterTransformer and Orca) at a similar level of latency. Sharing also enables prefix caching: requests that start with the same long system prompt can reuse its cached blocks instead of recomputing them. vLLM's automatic prefix caching and SGLang's RadixAttention (Zheng et al., 2024) do this.

Why this matters in practice: context windows of 128K tokens and more would be unthinkable with a materialised score matrix: at $n = 131{,}072$, $S$ is 32 GiB per head in 16-bit. FlashAttention-style kernels are now the default in LLM training, and paged KV caches are standard in serving engines such as vLLM, SGLang and TensorRT-LLM. Both are pure systems work: the model and its outputs don't change, only how the bytes move.
Explain it back · in two or three sentences

FlashAttention does more arithmetic than standard attention in training. Why is it still faster, and why is its answer exact?

Model answer: Attention is memory-bound: the time goes on moving the $n \times n$ matrices $S$ and $P$ through slow HBM, not on the arithmetic. FlashAttention keeps tiles in fast on-chip SRAM, never writes $S$ or $P$, and recomputes them in the backward pass, trading cheap FLOPs for expensive memory traffic. It is exact because the online-softmax update (running max $m$, running sum $\ell$, rescaling by $e^{m - m'}$) is an exact algebraic rewrite of the softmax, not an approximation.
Check yourself

In the online softmax, a new block raises the running max from $m$ to $m'$. What happens to the old running sum $\ell$ and accumulator $a$?

  1. They are thrown away and recomputed from the start of the row
  2. They are kept unchanged; only the new block uses $m'$
  3. Both are multiplied by $e^{m - m'}$, then the new block's terms are added
  4. Both are divided by $e^{m - m'}$
Multiplying by $e^{m-m'}$ (≤ 1) converts every old term $e^{s_j - m}$ into $e^{s_j - m'}$, so old and new terms share the same reference max. Keeping them unchanged would mix two different scales; dividing would scale them the wrong way.

Beyond its inputs and output, how much extra memory does FlashAttention's forward pass need for a sequence of length $n$?

  1. $O(n)$: a running max and sum per query row
  2. $O(n^2)$, but kept in SRAM instead of HBM
  3. $O(n^2)$ in HBM, same as standard attention
  4. $O(1)$, regardless of sequence length
The $n \times n$ matrices never exist in full anywhere; SRAM only holds one tile at a time (and couldn't hold $n^2$ numbers anyway). What survives per row is $m$ and $\ell$ (saved as the log-sum-exp), which is linear in $n$.

What problem does PagedAttention mainly solve?

  1. Attention needs too many FLOPs at long context
  2. The KV cache values need too many bits, so it quantizes them
  3. The softmax is numerically unstable
  4. KV-cache memory is wasted by max-length contiguous reservations, which limits how many requests fit in a batch
PagedAttention is memory management: fixed-size blocks allocated on demand, plus block tables, so almost no KV memory is reserved-but-empty and blocks can be shared. It doesn't change the attention math or the precision.

Interleaving with M1.1: a decoder LLM uses a causal mask. In a causal FlashAttention kernel, what happens to a $K/V$ tile that lies entirely in the "future" of a $Q$ tile?

  1. It is loaded and multiplied as usual, then the mask is applied to $O$
  2. It can be skipped entirely: every score in it would be $-\infty$, so its weights are exactly 0
  3. Its scores are divided by $\sqrt{d_k}$ twice
  4. It is written to HBM for the backward pass
Masked scores become $-\infty$ and $e^{-\infty} = 0$, so a fully masked tile contributes nothing to $m$, $\ell$ or $a$. Skipping such tiles roughly halves the work for causal attention. Tiles on the diagonal still get the usual element-wise mask, inside SRAM.

Key takeaways

  • GPU HBM is big but slow; on-chip SRAM is tiny but about 10× faster. Standard attention is memory-bound because it moves $n \times n$ matrices through HBM.
  • The online softmax keeps a running max $m$ and sum $\ell$, rescaling old terms by $e^{m - m'}$, so softmax can be computed block by block, exactly.
  • FlashAttention = tiling + online softmax + recomputation in one fused kernel: exact output, $O(n)$ extra memory, far less HBM traffic.
  • PagedAttention stores the KV cache in fixed-size blocks with per-request block tables: near-zero waste, sharing between samples and prefixes, and bigger batches.
