CNNs: filters, pooling & receptive fields

Lesson 1 of Classic deep-learning architectures

An MLP treats an image as a long, structureless list of numbers. A convolutional neural network (CNN) instead slides small learned filters across the picture, reusing the same few weights everywhere. That one idea took computer vision from reading zip codes to beating every hand-built system, and convolutions still sit inside today's image, audio and video models.

By the end you can

  • Count the parameters of a convolutional layer with channels, and compare it with a dense layer on the same image.
  • Explain what max and average pooling do, and compute a receptive field through a stack of layers.
  • Describe the edges → textures → parts → objects hierarchy and place LeNet-5, AlexNet and VGG on the timeline.
Builds on: MLPs (a layer is weights, a bias and a nonlinearity) and Convolution (sliding a kernel over a signal, stride, padding and the output-size formula). This lesson stacks those convolutions into a network.

Why images broke the MLP

In 1959 and 1962, David Hubel and Torsten Wiesel recorded single neurons in the cat visual cortex. Each "simple cell" responded to an edge at one orientation in one small patch of the visual field; "complex cells" responded to the same edge anywhere in a slightly larger patch. Kunihiko Fukushima turned that into a layered model, the Neocognitron (1980). Yann LeCun and colleagues then trained such a network end to end with backpropagation to read handwritten zip codes (LeCun et al., 1989), which led to LeNet-5 (LeCun, Bottou, Bengio & Haffner, 1998), later used to read the amounts on bank cheques.

Why not just use an MLP (P3.1)? Count. A 224×224 colour image is $224 \times 224 \times 3 = 150{,}528$ numbers. A dense layer from that image to a modest 1,000 hidden units needs $150{,}528 \times 1{,}000 + 1{,}000 \approx 150.5$ million parameters, for one layer, and it would have to learn "a vertical edge" separately at every one of the 50,176 pixel positions.

A convolutional layer makes two assumptions about images instead:

  • Local connectivity: each output looks only at a small patch (say 3×3), because nearby pixels are what form edges and textures.
  • Weight sharing: the same filter slides over every position, because an edge is an edge wherever it appears.

The payoff is huge. A 3×3 conv layer with 64 filters on the same image has just $1{,}792$ parameters, yet it produces 64 full-size feature maps, $224 \times 224 \times 64 \approx 3.2$ million outputs. A dense layer with that many outputs would need about 483 billion weights. Weight sharing also gives translation equivariance: shift the image and the feature maps shift with it.

Which two assumptions let a convolutional layer use so few parameters?

  1. Each output looks at a small patch, and the same filter is reused at every position
  2. Images are grayscale, and pixels are independent
  3. Only the centre of the image matters, and colours can be averaged
  4. Filters are fixed by hand, so nothing needs to be learned
Local connectivity plus weight sharing. The filter weights are still learned by gradient descent; they're just shared across all positions.

Conv layers and pooling

Real images and feature maps have channels: 3 for RGB, then 64, 128, … as the network deepens. A filter in a conv layer always spans all input channels: a "3×3 filter" on a 64-channel input is really a $3 \times 3 \times 64$ block of weights. Its output at one position is the dot product of that block with the input patch, plus a bias. Each filter produces one output channel (one feature map), so a layer with $C_{out}$ filters outputs $C_{out}$ channels.

$$\text{params} = k \cdot k \cdot C_{in} \cdot C_{out} \;+\; C_{out}$$

Here $k$ is the kernel's height and width, $C_{in}$ the number of input channels, $C_{out}$ the number of filters (output channels), and the final $C_{out}$ counts one bias per filter. The output's height and width follow the formula from P5.4, $\lfloor (n + 2p - k)/s \rfloor + 1$ for input size $n$, padding $p$ and stride $s$, and don't change the parameter count. After the convolution comes a nonlinearity (ReLU, as in P3.1), applied to every number.

Worked example

The second block of a VGG-style network: a 3×3 conv from 64 channels to 128 channels.

  1. Weights per filter: $3 \times 3 \times 64 = 576$
  2. All filters: $576 \times 128 = 73{,}728$
  3. Plus 128 biases: $73{,}856$ parameters ✓
  4. With padding 1 and stride 1, a $112 \times 112 \times 64$ input becomes $112 \times 112 \times 128$.

LeNet-5's first layer is the tiny version: six $5 \times 5$ filters on a one-channel $32 \times 32$ image, so $5 \cdot 5 \cdot 1 \cdot 6 + 6 = 156$ parameters and an output of $28 \times 28 \times 6$ (no padding).

Pooling: shrink the map, keep the signal

Classic CNNs alternate conv layers with pooling layers. A pooling layer slides a small window (usually $2 \times 2$ with stride 2) over each channel separately and replaces the window by one number:

  • Max pooling keeps the largest value: "was this feature present anywhere in the window?"
  • Average pooling keeps the mean: "how much of this feature is there, on average?"

Pooling has no parameters. A $2 \times 2$, stride-2 pool halves the height and the width, so it cuts the numbers in a feature map by 4 and makes later layers cheaper. It also buys a little tolerance to small shifts: if an edge moves by one pixel but stays inside the same window, the max doesn't change.

Worked example: pooling

Take one $4 \times 4$ channel, with rows $[1, 3, 2, 0]$, $[4, 2, 1, 1]$, $[0, 1, 5, 6]$ and $[2, 2, 7, 8]$. Split it into four $2 \times 2$ windows:

  1. Top-left window $\{1, 3, 4, 2\}$: max 4, average 2.5
  2. Top-right $\{2, 0, 1, 1\}$: max 2, average 1
  3. Bottom-left $\{0, 1, 2, 2\}$: max 2, average 1.25
  4. Bottom-right $\{5, 6, 7, 8\}$: max 8, average 6.5. So max pooling gives the $2 \times 2$ map $[4, 2]$, $[2, 8]$.

Modern designs often drop separate pooling layers and use a stride-2 convolution to downsample instead, so the network learns how to shrink. And instead of flattening the last feature map into huge dense layers (AlexNet and VGG put most of their parameters there), most CNNs since GoogLeNet (2014) end with global average pooling: average each channel over the whole map, giving one number per channel (Lin et al., 2013, "Network in Network").

A $56 \times 56 \times 128$ feature map goes through a $2 \times 2$ max pool with stride 2. What comes out?

  1. $56 \times 56 \times 64$
  2. $28 \times 28 \times 128$
  3. $28 \times 28 \times 64$
  4. $112 \times 112 \times 128$
Pooling works on each channel separately, so the channel count stays 128, and stride 2 halves height and width.

Receptive fields grow with depth

The receptive field of a unit is the patch of the input image that can influence it. In the first layer it's just the kernel, $3 \times 3$. But a second-layer unit reads a $3 \times 3$ patch of first-layer units, each of which saw its own $3 \times 3$ patch, and those patches overlap. Watch it grow:

For a stack of $L$ stride-1 layers with kernel size $k$, the receptive field is $1 + L(k-1)$. Strides and pooling make it grow faster: every layer after a stride-$s$ step adds $(k-1)$ times the product of all earlier strides. In symbols, with $j$ the running product of strides ("jump") before the current layer:

$$r \leftarrow r + (k - 1)\cdot j, \qquad j \leftarrow j \cdot s$$

starting from $r = 1$ and $j = 1$. Here $r$ is the receptive field so far (in input pixels), $k$ and $s$ are the current layer's kernel size and stride, and $j$ is how many input pixels one step in the current feature map spans.

Explain like I'm 5

Imagine a tall building full of detectives looking at a big painting. Each detective on the ground floor looks through a tiny window at just a few dabs of paint and shouts "I see a line!" or "I see red!"

Each detective on the next floor doesn't look at the painting at all. They listen to a few ground-floor detectives standing side by side, so they learn about a bigger piece: "a corner!" One floor higher, a detective hears about corners and curves and says "an eye!". At the top, someone says "a cat!"

Where it breaks: real filters aren't hand-assigned jobs like "find red". They are learned, and many respond to blends of things that are hard to name.

Worked example

conv 3×3 (stride 1) → max pool 2×2 (stride 2) → conv 3×3 → conv 3×3.

  1. conv: $r = 1 + 2 \cdot 1 = 3$, $j$ stays 1
  2. pool ($k = 2$, $s = 2$): $r = 3 + 1 \cdot 1 = 4$, then $j = 2$
  3. conv: $r = 4 + 2 \cdot 2 = 8$
  4. conv: $r = 8 + 2 \cdot 2 = 12$. Without the pool, three convs would only reach 7.

Run the same rule through all 13 conv and 5 pooling layers of VGG-16 and the last conv layer's units each see a $196 \times 196$ patch: almost the whole $224 \times 224$ image. In practice the effective receptive field is smaller: pixels near the centre reach a unit through many more paths than pixels at the edge, so the influence is roughly Gaussian (Luo et al., 2016).

VGG replaced big 7×7 filters with stacks of three 3×3 filters. Which is not a benefit of that swap?

  1. Fewer weights: $27C^2$ instead of $49C^2$
  2. Three nonlinearities instead of one, so the stack can compute more complex functions
  3. A larger receptive field than the 7×7 layer
  4. The same 7×7 receptive field
Three 3×3 layers see exactly 7×7, the same as one 7×7 layer. The gains are fewer weights and more nonlinearity (Simonyan & Zisserman, 2014).

From edges to objects: LeNet, AlexNet, VGG

What do the layers learn? Zeiler & Fergus (2014, "Visualizing and Understanding Convolutional Networks") projected the activations of a trained ImageNet CNN back into pixel space and found a clear feature hierarchy:

  1. Layer 1: oriented edges and colour blobs, much like Hubel and Wiesel's simple cells.
  2. Layers 2–3: corners, curves, then repeated textures and patterns (mesh, fur, text-like stripes).
  3. Layer 4: object parts, such as dog faces and bird legs.
  4. Layer 5: whole objects, recognised across different poses.

Small receptive fields can only see edges; large ones can see objects. The hierarchy is the receptive-field story, learned.

Three networks mark the path:

  • LeNet-5 (1998): about 60,000 parameters; conv → subsample → conv → subsample → fully connected, on $32 \times 32$ digits.
  • AlexNet (Krizhevsky, Sutskever & Hinton, 2012): about 60 million parameters, five conv layers plus three dense ones, trained on two GPUs with ReLU, dropout and data augmentation. It won the ImageNet challenge (ILSVRC-2012) with a top-5 error of 15.3%, against 26.2% for the runner-up. That gap is usually taken as the start of the deep-learning era.
  • VGG (Simonyan & Zisserman, 2014): 16–19 layers, using nothing but 3×3 convs and 2×2 pools. VGG-16 has about 138 million parameters, most of them in its final dense layers. It took second place in ILSVRC-2014 classification behind GoogLeNet, and its plain design made it a favourite backbone.

Going much deeper than VGG made training worse, not better. Fixing that is the next lesson, ResNets & normalization.

Where CNNs live today: Vision Transformers (V1.1) took over much of image recognition after 2020, and their very first step, cutting the image into patches and projecting each one, is usually implemented as a convolution whose stride equals its kernel size. Modernised CNNs such as ConvNeXt (Liu et al., 2022) remain competitive. The U-Net (Ronneberger et al., 2015), a CNN that downsamples and then upsamples, was the denoiser in most image diffusion models before diffusion transformers (G1.3). Convolutions also front speech models (Whisper's encoder begins with two 1-D convs, A1.2) and run inside neural audio codecs (A1.3) and Mamba-style sequence layers (AR.3).

In Zeiler & Fergus's visualisations, why do early layers show edges and later layers show object parts?

  1. Later units have much larger receptive fields, so they can combine earlier features into bigger patterns
  2. Later layers use bigger kernels than early ones
  3. Engineers hand-designed the later filters to look for objects
  4. Pooling removes all the edges before the later layers
With small kernels everywhere (as in VGG), a deeper unit's view is assembled from many smaller views, so it can respond to larger structures built from the features below.
Explain it back · in two or three sentences

Why does a CNN need far fewer parameters than an MLP on images, and how does a deep CNN still manage to recognise whole objects?

Model answer: A conv layer connects each output only to a small local patch and reuses the same filter at every position, so its parameter count is $k \cdot k \cdot C_{in} \cdot C_{out} + C_{out}$, independent of the image size. Stacking layers (plus pooling or strides) makes each unit's receptive field grow, so deeper units combine edges into textures, parts and finally whole objects.
Check yourself

How many parameters does a 1×1 conv from 256 channels to 64 channels have, with biases?

  1. 320
  2. 16,448
  3. 147,520
  4. It depends on the image size
$1 \cdot 1 \cdot 256 \cdot 64 + 64 = 16{,}448$. A 1×1 conv mixes channels at each pixel without looking at neighbours: it's a small dense layer applied at every position. ResNet's bottleneck blocks (next lesson) use them to shrink and re-grow channels.

What does a 2×2 max-pooling layer learn during training?

  1. One weight per window position
  2. A separate weight for each channel
  3. The best window size
  4. Nothing: it has no parameters
Pooling is a fixed operation. Gradients pass through it (for max pooling, only to the input that was largest), but there is nothing to update.

conv 3×3 → conv 3×3 → max pool 2×2 (stride 2) → conv 3×3, all convs with stride 1. What is the final receptive field?

  1. 7
  2. 8
  3. 10
  4. 12
$r$: 3, 5, then the pool adds 1 (to 6) and sets $j = 2$, then the last conv adds $2 \times 2 = 4$: 10.

Interleaving with P3.1: a conv layer is "a dense layer with constraints". Which constraints?

  1. Most weights are forced to zero (only a local patch connects), and the remaining weights are tied across positions
  2. All weights must be positive
  3. There is no nonlinearity after a conv layer
  4. Each output connects to every input with its own unique weight
Write a conv as a big matrix multiply and you get a sparse matrix whose rows repeat the same few weights, shifted. It's still followed by a nonlinearity like ReLU, just as in an MLP.

Key takeaways

  • Conv layers use local connectivity and weight sharing: parameters $= k \cdot k \cdot C_{in} \cdot C_{out} + C_{out}$, whatever the image size.
  • Each filter spans all input channels and produces one output channel (feature map).
  • Pooling (max or average) downsamples each channel with no parameters; stride-2 convs and global average pooling are the modern variants.
  • Stacked layers grow the receptive field: $1 + L(k-1)$ at stride 1, faster after strides. Three 3×3 layers see 7×7 with fewer weights than one 7×7.
  • LeNet-5 (1998) → AlexNet (2012) → VGG (2014): deeper nets, small filters, learned edges → textures → parts → objects.
