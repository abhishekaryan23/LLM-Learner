Contamination

Lesson 3 of Evaluation

A benchmark only measures skill if the model hasn't seen the test. But LLMs are pretrained on a large slice of the public web, and benchmarks live on the public web. When test questions leak into training data, scores go up without the model getting any better. This is contamination.

  • Describe four detection methods (n-gram overlap, canary strings, perturbed variants, membership inference) and their blind spots.
  • Choose mitigations: decontamination filters, private held-out sets and fresh, dated benchmarks.

A model scores much higher on an old, widely shared benchmark than on freshly written questions of the same type and difficulty. What's the most likely explanation?

  1. Some of the old test questions, or close copies, were in its training data
  2. The new questions must be harder
  3. Models get worse over time
  4. Old benchmarks use an easier metric
If difficulty is matched, a gap between old and fresh questions is the classic sign of contamination: some old answers were remembered rather than worked out.

Some benchmark files contain a long random string with a note saying it should never appear in training data. What is it for?

  1. It's a licence key for the dataset
  2. It encrypts the answers
  3. It lets training pipelines filter the files out, and lets anyone test whether a model has seen them
  4. It makes the questions harder for the model
That's a canary string. Filters can drop any document containing it, and if a model can complete the string from its first few characters, the benchmark files were probably in its training data.

How test data leaks

Pretraining corpora are built from huge web crawls (M2.1). Benchmarks are public by design, so their questions turn up in many places: GitHub repos and dataset hubs, paper appendices, blog posts walking through examples, forum threads asking for help on a question, and translations of all of these. Nobody has to cheat on purpose. At trillions of tokens, it's simply hard to keep every copy out.

Leaks come in different strengths:

  • Exact: the question and answer appear verbatim.
  • Near-duplicate: reformatted, reworded slightly or with different whitespace.
  • Semantic: paraphrased or translated. The same problem, but few shared words.
  • Input only vs input + label: seeing the question alone helps a little; seeing it with its answer helps a lot.

Post-training can leak too: a fine-tuning set that copied benchmark items, or synthetic data generated by a model that had memorised them.

Why it inflates scores

A test set is supposed to measure generalisation: performance on problems the model has never seen (P2.4). A contaminated item measures recall instead. The overall score becomes a blend of a real skill and a memory test, and you can't tell how much of each from the number alone.

There is real evidence that this matters. Zhang et al. (2024) wrote GSM1k, 1,250 new grade-school problems matched to GSM8K's style and difficulty. Some model families scored noticeably lower on the fresh problems than on GSM8K, while several frontier models showed little or no drop. LiveCodeBench (Jain et al., 2024) dates every coding problem by its contest release; for some models, performance fell off sharply on problems released after the model's training cutoff. Both patterns are what contamination predicts.

Explain like I'm 5

A student finishes the test in ten seconds and gets everything right. Wow! But there's an answer sheet poking out of their pocket. They saw the answers before the test.

The teacher raises an eyebrow and does the smart thing: she changes the numbers in the questions. A student who really understands still gets them right. A student who only remembered the answers suddenly gets them wrong.

Where it breaks: the model isn't sneaky. It read the whole internet, and the answer sheet happened to be lying around in it. Nobody meant to peek.

Detecting contamination

1 · n-gram overlap (needs the training data)

Normalise text, split every test item into overlapping word $n$-grams, and look them up in an index of the training corpus. A sequence of $L$ words has $L - n + 1$ $n$-grams. GPT-3 (Brown et al., 2020) flagged test items sharing 13-grams with the training data, and reported scores on the “clean” subset too. The GPT-4 report (OpenAI, 2023) checked for 50-character substrings. Blind spots: paraphrases and translations slip through, and very common phrases cause false alarms, so the choice of $n$ and threshold matters.

2 · Canary strings

BIG-bench (Srivastava et al., 2022) put a unique GUID, a canary string, in its files with a request not to train on them. Training pipelines can drop any document that contains it, and if a model can reproduce the canary from its first characters, the files were probably in its training data. Blind spot: copies of the questions without the canary, such as quotes in a blog post, escape both checks.

3 · Perturbed and rephrased variants (black box)

Change the numbers or names, shuffle the multiple-choice options, or paraphrase the question, keeping the difficulty the same. A model that solves the problem barely notices. A model that memorised the item drops, or even repeats the old answer. Fresh look-alike sets such as GSM1k are this idea at scale. Blind spot: it's hard to make variants exactly as difficult as the originals.

4 · Membership inference

Text a model was trained on tends to get an unusually high likelihood, that is, unusually low perplexity (M4.1). Min-K% Prob (Shi et al., 2024) averages the log-probabilities of the least likely k% of tokens: if even the hardest tokens of a passage are predicted well, the passage was probably seen. Oren et al. (2024) test whether a model prefers a dataset's original example order over shuffled orders, which only makes sense if it saw the dataset in that order. Blind spot: these are statistical hints, not proof. Duan et al. (2024) found that many such attacks barely beat chance on LLM pretraining data.

Worked example: how much does it inflate?

A benchmark has 1,000 items. Decontamination analysis finds 200 of them in the training data. The model gets 95% of the contaminated items right and 60% of the clean ones.

  1. Correct answers: $200 \times 0.95 + 800 \times 0.60 = 190 + 480 = 670$.
  2. Reported score: $670 / 1000 = 67\%$.
  3. Clean-subset score: $60\%$. That's the better estimate of the real skill.
  4. Inflation: $67 - 60 = 7$ percentage points, which is bigger than many gaps between competing models.

Preventing it

  • Decontaminate the training data: before training, remove or mask documents that overlap known test sets, and say what you removed. Then report scores on the clean subset alongside the full one.
  • Keep test sets private: publish a dev set, but keep the real test questions, or at least their answers, off the internet, and score submissions on a server, as Kaggle-style private leaderboards do. Combine with a canary string for the parts that are public.
  • Use fresh, dated benchmarks: LiveCodeBench (Jain et al., 2024) keeps collecting new contest problems so you can evaluate only on problems released after a model's training cutoff; LiveBench (White et al., 2024) refreshes its questions regularly. These help a lot, but they aren't perfect: cutoff dates are self-reported and fuzzy, new problems can resemble old ones, and difficulty drifts from batch to batch.
  • Protect your own evals: the private test set you build for your product (M4.7) is only useful while it stays private. Don't post it publicly.
Why this matters in practice: serious model reports now include a contamination section, and the habit is worth copying. When a new model jumps on an old, famous benchmark but not on fresh ones, suspect contamination before celebrating. Prefer benchmarks with private or dated test sets for decisions, and read “we decontaminated against X” as a claim about exact or near-exact overlap, not about paraphrases.
Explain it back · in two or three sentences

Why can a decontamination filter based on 13-gram overlap still leave a benchmark contaminated, and what black-box check could reveal it?

Model answer: n-gram filters only catch text that shares long exact word sequences with the test item, so paraphrased, reformatted or translated copies slip through. A black-box check is to perturb the items (new numbers, shuffled options, paraphrases) or use a fresh, matched set: if accuracy drops clearly, or the model repeats the original answer, it likely memorised the originals.
Check yourself

Contamination is the LLM-scale version of which classic machine-learning mistake?

  1. Using a learning rate that's too high
  2. Leaking test examples into the training data, so the test no longer measures generalisation
  3. Training for too few epochs
  4. Using too small a batch size
Train/test separation (P2.4) is what makes a test score mean “works on unseen data”. Contamination breaks that separation, so part of the score measures memory.

Membership-inference methods like Min-K% Prob look for which signal that a passage was in the training data?

  1. The passage contains a canary string
  2. The model refuses to discuss the passage
  3. The passage has many long words
  4. The model assigns it unusually high likelihood (low perplexity), even on its hardest tokens
Training pushes up the likelihood of seen text (M4.1), so seen passages tend to have fewer “surprising” tokens. It's a statistical hint, not proof.

Which contamination would a 13-gram overlap filter most likely miss?

  1. A French translation of the test questions
  2. A verbatim copy of the test file on GitHub
  3. The test questions with extra blank lines between them
  4. The test questions in all capital letters
Normalisation (lowercasing, collapsing whitespace) handles the formatting cases. A translation shares almost no word sequences with the original, so overlap filters can't see it.

You're publishing a new benchmark and want it to stay useful for years. Which plan is best?

  1. Publish all questions and answers so everyone can reproduce results
  2. Publish the questions without a canary string, so filters don't remove them
  3. Keep a private held-out test split, add a canary to public files, and refresh with new dated items over time
  4. Make the questions as hard as possible so models can't memorise them
Private test data can't be crawled, canaries let others filter and check the public part, and fresh dated items let you evaluate after each model's cutoff. Hard questions can still be memorised once their answers are online.

Key takeaways

  • Contamination = test items (or close copies) in the training data. Scores then mix skill with memory.
  • Detection: n-gram overlap (needs the data), canary strings, perturbed or fresh variants (black box) and membership inference (statistical hints).
  • Paraphrases and translations defeat overlap filters, so no single check is enough.
  • Mitigation: decontaminate and report clean-subset scores, keep private held-out sets, and prefer fresh, dated benchmarks.
