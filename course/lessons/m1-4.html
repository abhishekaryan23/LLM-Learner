The decoder-only transformer

Lesson 4 of Transformers

You now have every part. This lesson snaps them together into the architecture behind GPT, Llama, Claude and nearly every other LLM: a stack of identical-looking layers wrapped around one long “residual stream”. Then you'll count every one of GPT-2 small's 124 million parameters.

  1. 1, the token after the end
  2. About 1,000, one per position
  3. About 1,000,000, one per pair of tokens
  4. None; it has to generate first
Every position predicts its own next token at the same time, and the causal mask stops each one seeing its answer. That parallelism is a big reason transformers train so efficiently.

The whole model, bottom to top

A decoder-only transformer turns $n$ input tokens into $n$ probability distributions over the next token:

  1. Token embedding: look up each token ID in a $V \times d_{\text{model}}$ table ($V$ is the vocabulary size). Older models also add a learned position vector here; RoPE models don't (M1.3).
  2. $N$ layers, each: normalize → causal multi-head self-attention → add; normalize → MLP → add.
  3. Final norm, then the unembedding $W_U$ ($d_{\text{model}} \times V$) gives a score, a logit, for every vocabulary token.
  4. Softmax turns each position's logits into probabilities for the next token.

The residual stream

Write $h$ for the $n \times d_{\text{model}}$ matrix of token vectors (one row per token). Each layer does two updates:

$$h \leftarrow h + \mathrm{Attn}\big(\mathrm{Norm}(h)\big)$$ $$h \leftarrow h + \mathrm{MLP}\big(\mathrm{Norm}(h)\big)$$

Nothing ever replaces $h$; each sub-block reads a normalized copy and adds its contribution. That running sum is called the residual stream (Elhage et al., 2021, “A Mathematical Framework for Transformer Circuits”). Two consequences:

  • Training stays stable at depth. The “+ h” path is an identity, so gradients flow straight down through dozens of layers, the same trick that made very deep ResNets trainable (He et al., 2016).
  • Layers communicate through a shared space. Any layer can write information that any later layer reads. Each layer tends to nudge the representation rather than rebuild it.

The two sub-blocks have different jobs. Attention is the only place tokens exchange information: it moves information between positions. The MLP works on each token on its own; it's where much of the per-token processing happens, and interpretability work suggests a lot of factual association is stored there.

Explain like I'm 5

A lump of clay rides an elevator up a tall building. On every floor there's a workstation that looks just like the others.

Each station doesn't throw the clay away and start over. It adds a little touch: smooths a bump, shapes the neck a bit more. Floor by floor, the lump turns into a vase.

The clay is the token's vector, the elevator is the residual stream, the stations are layers. Where it breaks: each real station has its own learned tools (its own weights), and at the attention step the lumps on a floor can peek at each other.

Normalization: pre-norm, LayerNorm, RMSNorm

The original 2017 transformer normalized after each add (“post-norm”). GPT-2 moved the norm to the input of each sub-block (“pre-norm”, as in the equations above) and added one final norm before the unembedding. Pre-norm keeps the residual path clean and trains more reliably, needing less careful learning-rate warm-up (Xiong et al., 2020). Nearly every LLM since uses it.

LayerNorm rescales each token's vector to mean 0 and variance 1, then applies a learned scale and shift. Many modern models (Llama, Mistral, Gemma) use the simpler RMSNorm (Zhang & Sennrich, 2019), which skips the mean and the shift:

$$\mathrm{RMSNorm}(x) = \frac{x}{\sqrt{\tfrac{1}{d}\sum_{j=1}^{d} x_j^2 + \epsilon}} \odot g$$

$x$ is one token's vector of length $d$; the square root is its root-mean-square size; $\epsilon$ is a tiny constant to avoid dividing by 0; $g$ is a learned per-dimension gain; $\odot$ multiplies entry by entry.

The MLP

GPT-2's MLP is two matrices with a nonlinearity between: $\mathrm{MLP}(x) = \mathrm{GELU}(xW_1 + b_1)\,W_2 + b_2$, where $W_1$ expands $d_{\text{model}}$ to $4\,d_{\text{model}}$ and $W_2$ shrinks it back. Modern models mostly use SwiGLU (Shazeer, 2020, “GLU Variants Improve Transformer”): $\big(\mathrm{SiLU}(xW_1) \odot xW_3\big)\,W_2$. It has three matrices, so the hidden size is usually cut to about $\tfrac{8}{3}d_{\text{model}}$ to keep a similar parameter count, though many models pick larger (Llama 3 8B uses 14,336 for $d_{\text{model}} = 4096$, 3.5×).

Counting the parameters

Here's GPT-2 small: vocabulary $V = 50{,}257$, context 1,024, $d = d_{\text{model}} = 768$, $N = 12$ layers, 12 heads. It uses learned positions, LayerNorm, biases, a 4× GELU MLP, and tied embeddings ($W_U$ is the transpose of the token embedding, so it adds no parameters).

  1. Token embedding: $50{,}257 \times 768 = 38{,}597{,}376$.
  2. Position embedding: $1{,}024 \times 768 = 786{,}432$.
  3. Attention, per layer: $W_Q, W_K, W_V$ as one $768 \times 2304$ matrix plus 2,304 biases $= 1{,}771{,}776$; $W_O$ is $768 \times 768$ plus 768 biases $= 590{,}592$. Total $2{,}362{,}368$, about $4d^2$.
  4. MLP, per layer: $768 \times 3072 + 3072 = 2{,}362{,}368$ and $3072 \times 768 + 768 = 2{,}360{,}064$. Total $4{,}722{,}432$, about $8d^2$.
  5. Two LayerNorms, per layer: $2 \times (768 + 768) = 3{,}072$. So one layer is $7{,}087{,}872$, and 12 layers are $85{,}054{,}464$.
  6. Final LayerNorm $1{,}536$; unembedding tied, $0$. Grand total: $38{,}597{,}376 + 786{,}432 + 85{,}054{,}464 + 1{,}536 = 124{,}439{,}808$, the famous “124M” ✓

Dropping the small terms gives a rule of thumb worth memorizing:

$$\text{params} \approx \underbrace{12\,N\,d_{\text{model}}^2}_{\text{layers}} + \underbrace{V\,d_{\text{model}}}_{\text{embeddings}}$$

For GPT-2 small: $12 \times 12 \times 768^2 = 84{,}934{,}656$, within 0.2% of the exact layer total. GQA (M1.2) and SwiGLU change the constant 12 somewhat.

Training vs generation

Training feeds a whole sequence at once. The output is an $n \times V$ grid of logits, and position $t$'s logits are scored against the true token at $t+1$ with cross-entropy (M2.2). Because of the causal mask, no position can see its own answer, so one forward pass yields $n - 1$ graded predictions. Feeding the true previous tokens, rather than the model's own guesses, is called teacher forcing.

Generation is a loop: run the model on the text so far, keep only the last position's distribution, pick a token from it, append it, and repeat. Run naively, every step recomputes all earlier positions, which is wasteful. The fix, the KV cache, and the ways to “pick a token” are the subject of M1.5.

Why this matters in practice: parameter counts drive everything downstream. A forward pass costs roughly $2$ FLOPs per parameter per token, and training roughly $6$ (Kaplan et al., 2020), which is how compute budgets in scaling laws are estimated. The memory for weights is params × bytes per parameter: 124M parameters in 16-bit floats is about 250 MB, and an 8B model about 16 GB, before any KV cache. Architecture variants (GQA, SwiGLU, RMSNorm, untied embeddings) change these totals in ways you can now compute yourself from a model's config file.

Explain the residual stream, and the different jobs of attention and the MLP inside one layer.

Model answer: Each token has a vector that's carried up through all the layers; every sub-block reads a normalized copy of it and adds its output back, so the stream is a running sum that layers write to and read from, and gradients flow straight through the additions. The MLP then processes each token separately, and holds about two thirds of a layer's parameters.

  2. Only once, after the embedding
  3. Only to the logits

Suppose you switched GPT-2 small from learned positions to RoPE (M1.3), keeping everything else. Its parameter count would…

  1. grow, because every head needs rotation matrices
  2. stay exactly the same
  3. drop by 786,432, the size of the position table, since RoPE's rotations are fixed formulas
  4. double
RoPE has no learned parameters: the angles $m\theta_i$ come from a formula. Removing the $1{,}024 \times 768$ table saves 786,432 parameters.

Key takeaways

  • Embedding → $N$ × [norm → attention → add; norm → MLP → add] → final norm → unembedding → softmax.
  • The residual stream is a running sum: layers read normalized copies and add their results.
  • Attention moves information between tokens; the MLP processes each token and holds ≈ ⅔ of layer parameters.
  • Rule of thumb: params ≈ $12\,N\,d_{\text{model}}^2 + V\,d_{\text{model}}$. GPT-2 small is exactly 124,439,808.
  • Training scores every position in parallel; generation loops one token at a time.
