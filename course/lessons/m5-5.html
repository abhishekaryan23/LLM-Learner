Speculative decoding

Lesson 5 of Optimization

Generating text one token at a time leaves a big GPU mostly waiting on memory. Speculative decoding lets a small, fast model guess a few tokens ahead and the big model check all the guesses at once. With the right accept/reject rule, the text you get is distributed exactly as if the big model had written it alone, just sooner.

By the end you can

  • Explain why decoding is memory-bandwidth-bound, and why checking $k$ tokens costs about as much as generating one.
  • Apply the acceptance rule $\min(1, p/q)$ and the residual resampling step, and show why the output distribution is exactly the target's.
  • Compute the expected tokens per step, $(1-\alpha^{k+1})/(1-\alpha)$, and the resulting speedup.
Before you start: you'll need KV cache & sampling (generating one token per forward pass, sampling from a probability distribution) and the idea of a memory-bound operation from FlashAttention & paged attention. Draft models are often small distilled models (M5.2, optional).
Warm-up · guess before you learn

A guess now makes the answer stick later.

An 8B-parameter model generates text for a single user on a big GPU. Each new token mostly waits on…

  1. reading all the model's weights from GPU memory
  2. the multiply-adds of the forward pass
  3. the tokenizer
  4. sampling from the softmax
Every decode step reads every weight once to produce just one token per sequence. The GPU can do the arithmetic hundreds of times faster than it can stream the weights.

A small "draft" model guesses the next 4 tokens and a big model checks them. Can the final text be distributed exactly as if the big model had generated it alone?

  1. No, the draft always makes quality slightly worse
  2. Yes, with the right probabilistic accept/reject rule
  3. Only with greedy decoding (temperature 0)
  4. Only if the draft model is the same size as the big one
Speculative sampling is provably lossless: accepting each guess with probability $\min(1, p/q)$ and resampling cleverly on rejection gives exactly the big model's distribution, at any temperature.

Why one token at a time is wasteful

To generate a token, a decoder runs a forward pass, and a forward pass must read every weight from GPU memory. Take an 8B-parameter model in 16-bit on an H100 (about 3.35 TB/s of memory bandwidth, about 990 TFLOP/s of dense 16-bit compute):

  • Memory: 16 GB of weights ÷ 3.35 TB/s ≈ 4.8 ms per step, so at most about 210 tokens/s for one user.
  • Compute: about $2 \times 8 \times 10^9 = 16$ GFLOP per token ÷ 990 TFLOP/s ≈ 0.016 ms.

The arithmetic units are idle more than 99% of the time. That's what memory-bandwidth-bound means. Now the key observation: if we hand the model 5 tokens in one forward pass (like during prefill), it still reads the weights only once. The time barely changes, and we get the model's prediction at all 5 positions. Checking several tokens is almost as cheap as generating one.

These are idealised peak numbers; real kernels reach less, and the KV cache adds more reads. The ratio is what matters: about 1 FLOP per byte at batch size 1, while an H100 needs roughly 300 to keep its compute busy.

Guess, then verify

That suggests a plan. Let a small draft model (probabilities $q$) cheaply guess the next $k$ tokens. Then let the big target model (probabilities $p$) score all of them in one pass, keep the good guesses, and fix the first bad one. The idea was published independently by Leviathan, Kalman & Matias (2023, "Fast Inference from Transformers via Speculative Decoding") and Chen et al. at DeepMind (2023, "Accelerating Large Language Model Decoding with Speculative Sampling").

One round, precisely:

  1. The draft samples $x_1, \dots, x_k$ one by one, recording $q_i(x_i)$.
  2. The target runs one forward pass on the prefix plus $x_1, \dots, x_k$, giving distributions $p_1, \dots, p_{k+1}$.
  3. For $i = 1, \dots, k$: draw $u \sim \mathrm{Uniform}(0,1)$ and accept $x_i$ if $u < \min\!\big(1, \frac{p_i(x_i)}{q_i(x_i)}\big)$.
  4. At the first rejection, sample a replacement from the normalised residual $p'(x) = \dfrac{\max(0,\ p_i(x) - q_i(x))}{\sum_y \max(0,\ p_i(y) - q_i(y))}$, discard the remaining drafts, and stop.
  5. If all $k$ were accepted, sample one bonus token from $p_{k+1}$, which the target computed anyway.

Each round yields between 1 and $k+1$ tokens for one target pass. Rejected drafts' entries are simply dropped from the KV cache.

Why the output is exactly the target's distribution

Look at one position. Write $p(x)$ and $q(x)$ for the two models' probabilities there. The output is $x$ either because the draft proposed $x$ and it was accepted, or because some draft was rejected and the residual produced $x$:

$$P(\text{out} = x) = \underbrace{q(x)\,\min\!\Big(1, \tfrac{p(x)}{q(x)}\Big)}_{=\ \min(p(x),\ q(x))} \;+\; P(\text{reject})\cdot p'(x)$$

The chance of a rejection is $1 - \sum_y \min(p(y), q(y)) = \sum_y \max(0, p(y) - q(y))$, because the probabilities sum to 1. That is exactly the residual's normaliser, so the second term is simply $\max(0, p(x) - q(x))$. And

$$\min(p, q) + \max(0,\ p - q) = p \qquad\text{for any numbers } p, q \ge 0.$$

So $P(\text{out} = x) = p(x)$: exactly the target's distribution, whatever the draft model is. A bad draft only makes things slower, never worse. The per-token acceptance chance is $\beta = \sum_x \min(p(x), q(x))$, which is one minus the total-variation distance between $p$ and $q$. Its average over the text is the acceptance rate $\alpha$.

Worked example

Vocabulary of three tokens A, B, C. Target $p = [0.5, 0.3, 0.2]$, draft $q = [0.2, 0.6, 0.2]$.

  1. Draft proposes A: $p/q = 2.5$, so it's always accepted. Same for C ($p/q = 1$).
  2. Draft proposes B: accept with probability $\min(1, 0.3/0.6) = 0.5$.
  3. Residual: $\max(0, p - q) = [0.3, 0, 0]$, normalised $[1, 0, 0]$. A rejected B always becomes A.
  4. Check: $P(A) = 0.2 \cdot 1 + 0.6 \cdot 0.5 \cdot 1 = 0.5$ ✓, $P(B) = 0.6 \cdot 0.5 = 0.3$ ✓, $P(C) = 0.2$ ✓. Exactly $p$.
  5. Acceptance chance $\beta = \min(0.5, 0.2) + \min(0.3, 0.6) + \min(0.2, 0.2) = 0.7$.
Explain like I'm 5

A master builder is slow because every block takes him a long walk to fetch. His apprentice is quick, so she lays a whole row of blocks herself, guessing what the master would pick.

The master looks along the row in one glance. The first few blocks are just what he wanted, so he keeps them. At the first wrong block he swaps in his own choice, and the blocks after it come off. Then the apprentice starts the next row.

Because the master checks every block and fixes the first wrong one himself, the wall ends up exactly the way he would have built it, only much faster.

Where it breaks: the real "master" doesn't judge blocks right or wrong. He keeps each one with a probability, $\min(1, p/q)$, and swaps in a block chosen from what the apprentice under-picked, which is what keeps the result exact.

How much faster? Acceptance rate and draft length

Assume, as Leviathan et al. do for their analysis, that each draft token is accepted independently with probability $\alpha$. A round yields $n$ tokens when the first $n-1$ drafts are accepted and the next is rejected, and $k+1$ tokens when all $k$ are accepted. Summing up:

$$\mathbb{E}[\text{tokens per target pass}] = 1 + \alpha + \alpha^2 + \dots + \alpha^k = \frac{1 - \alpha^{k+1}}{1 - \alpha}$$

Here $\alpha$ is the acceptance rate and $k$ the number of drafted tokens. With $\alpha = 0.8$ and $k = 4$: $(1 - 0.8^5)/0.2 = (1 - 0.328)/0.2 = 3.36$ tokens per target pass.

Drafting isn't free. If one draft pass costs a fraction $c$ of a target pass, a round costs $1 + ck$ target passes, and the speedup over ordinary decoding is about

$$\text{speedup} \approx \frac{1 - \alpha^{k+1}}{(1 - \alpha)(1 + ck)}$$

With $c = 0.05$ (a draft about 20× cheaper): $3.36 / 1.2 \approx 2.8\times$. Notice that every extra draft token needs all earlier ones accepted, so the gain from bigger $k$ shrinks quickly. Try it:

In the papers, Leviathan et al. reported about 2–3× faster T5-XXL (11B) decoding, and Chen et al. about 2–2.5× for the 70B Chinchilla, with no change to the outputs. Real speedups vary a lot. Acceptance is high on predictable text such as code or text that repeats the prompt, and lower on open-ended creative writing. They also shrink at large batch sizes: a busy server's GPU is already doing useful arithmetic, so the "free" verification isn't free any more (M5.6).

Variants: where do the drafts come from?

  • A small model from the same family, such as a 1B model drafting for a 70B one. It must use the same tokenizer. It is often distilled from the target to raise $\alpha$.
  • Medusa (Cai et al., 2024) adds a few extra decoding heads to the target itself, each predicting a token further ahead, and verifies a tree of candidates in one pass using tree attention. Its optional "typical acceptance" rule trades exactness for speed.
  • EAGLE (Li et al., 2024; later EAGLE-2 and EAGLE-3) drafts with a light head that works on the target's own hidden features rather than tokens, and is among the fastest lossless methods reported.
  • Prompt lookup / n-gram drafting needs no draft model at all. It copies the continuation of a matching n-gram from the prompt, which works well when the output repeats the input (summaries, code edits, retrieval-augmented answers).

Reported speedups for these methods depend heavily on the model, task, hardware and batch size, so compare them on your own workload. Models trained with multi-token-prediction heads (for example DeepSeek-V3, 2024) can reuse those heads as drafters.

Why this matters in practice: speculative decoding is a standard option in serving engines such as vLLM, SGLang and TensorRT-LLM. It shines where latency matters and batches are small, as in interactive chat and coding assistants. With the standard accept/reject rule the output distribution is unchanged in exact arithmetic, so quality should not move. Still run your quality evals when you turn it on: implementations differ numerically, and some popular variants (such as typical or relaxed acceptance) trade exactness for speed. You also pay in memory for the drafter and its KV cache, and the gain fades as batch size grows.
Explain it back · in two or three sentences

Why does speculative decoding speed things up, and why doesn't it change what the model outputs?

Model answer: Decoding is memory-bound: each step reads all the weights to produce one token, so the target can score $k$ drafted tokens in one pass for about the cost of one step, and every accepted draft is a token gained. It's exact because each draft is accepted with probability $\min(1, p/q)$ and a rejection is replaced by a sample from the normalised $\max(0, p - q)$; together these give $\min(p,q) + \max(0, p-q) = p$, the target's own distribution.
Check yourself

The draft gave its token probability $q = 0.5$; the target gives it $p = 0.2$. What happens?

  1. It is always rejected, because $p < q$
  2. It is accepted with probability 0.2
  3. It is accepted with probability 0.4
  4. It is accepted with probability 0.7
Accept with probability $\min(1, p/q) = 0.2/0.5 = 0.4$. Rejecting it always would under-produce this token: the target still wants it 20% of the time.

After a rejection, the replacement token is sampled from…

  1. $\max(0, p - q)$, renormalised
  2. the draft distribution $q$
  3. the target distribution $p$
  4. a uniform distribution over the vocabulary
The accept step already produced $\min(p, q)$ of each token's probability. The residual supplies exactly the missing part, $p - \min(p,q) = \max(0, p - q)$. Sampling from $p$ would double-count tokens the draft already covers.

With acceptance rate $\alpha = 0.5$ and $k = 3$ drafts, how many tokens does each target pass produce on average?

  1. 1.5
  2. 1.875
  3. 2.0
  4. 4
$(1 - 0.5^4)/(1 - 0.5) = 0.9375/0.5 = 1.875$, i.e. $1 + 0.5 + 0.25 + 0.125$. The maximum is 4 (all three drafts plus the bonus token), but that needs all three accepted.

Interleaving with M1.5: with greedy decoding (temperature 0), $p$ and $q$ put all their probability on their top token. What does verification become?

  1. Every draft is accepted
  2. Drafts are accepted with probability 0.5
  3. The target re-generates every token one by one
  4. Keep drafts while they equal the target's top token; at the first mismatch, use the target's top token instead
With one-hot distributions, $p(x)/q(x)$ is 1 if the target's argmax is the drafted token and 0 otherwise, and the residual is one-hot on the target's argmax. So the output is exactly what greedy decoding of the target would produce.

Key takeaways

  • Decoding at small batch sizes is memory-bound: scoring $k$ extra tokens in one pass costs about the same as one step.
  • A draft proposes $k$ tokens; the target verifies all of them in one forward pass and yields 1 to $k+1$ tokens.
  • Accept with $\min(1, p/q)$; on rejection, resample from normalised $\max(0, p - q)$. The output is exactly the target's distribution.
  • Expected tokens per pass: $(1 - \alpha^{k+1})/(1 - \alpha)$; speedup ≈ that divided by $1 + ck$. Gains flatten as $k$ grows and shrink at large batch sizes.
  • Drafts can come from a small model, extra heads (Medusa, EAGLE) or the prompt itself (n-gram lookup).
