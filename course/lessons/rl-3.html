Q-learning & DQN

Lesson 3 of Reinforcement learning

Value iteration needs a perfect model of the world. Real agents don't have one: they just act and see what happens. Q-learning learns optimal action values from that raw experience, one transition at a time. Put a neural network in place of its table and you get DQN, the system that learned to play Atari games from pixels.

  • Say why Q-learning is off-policy and why it still needs exploration.
  • Name DQN's three key ingredients and explain how Double DQN reduces overestimation.

Warm-up · guess before you learn

Take your best guess. A wrong guess now makes the right answer stick later.

You estimate a trip home takes 30 minutes. Ten minutes in, traffic is bad and you now expect 25 more. When should you revise your estimate of the whole trip?

  1. Only when you arrive and know the true time
  2. Never: first estimates are best
  3. Right now: 10 + 25 = 35 is already a better guess than 30
  4. Only if you take a different route
Updating a guess from a better-informed later guess, without waiting for the final outcome, is temporal-difference learning. Sutton used this commute example himself.

An agent learns from games played by a random, clumsy policy. Can it still learn the values of the best policy?

  1. Yes, if its update assumes the best action will be taken next, whatever the clumsy policy actually does
  2. No, you can only learn about the policy that generated the data
  3. Only if the clumsy policy wins most games
  4. Only with a perfect model of the game
That's Q-learning's trick: its target uses $\max_{a'}$, the best next action, so it learns about the optimal policy from anyone's experience. This is called off-policy learning.

Learning from experience: temporal differences

Value iteration (RL.2) sweeps every state and needs the transition probabilities $P(s' \mid s,a)$. A robot, a game player or a chatbot has neither: it can only try actions and observe one next state and one reward at a time. How do you estimate values from samples?

The obvious way is Monte Carlo: play a whole episode, compute the actual return $G_t$, and nudge $V(s_t)$ toward it. It works, but you must wait until the episode ends, and returns are noisy because they add up many random steps.

Richard Sutton's temporal-difference (TD) learning (1988) updates after every step instead. It replaces the unknown rest of the return with the agent's own current estimate of the next state, a trick called bootstrapping:

$$V(s) \leftarrow V(s) + \alpha\,\big[\,\underbrace{r + \gamma V(s')}_{\text{TD target}} - V(s)\,\big]$$

$\alpha$ is a small step size (a learning rate). The bracket is the TD error $\delta$: how much better or worse things look one step later than you expected. It's the Bellman expectation equation (RL.2) used as an update on a single sample, with no model required. TD-Gammon (RL.1) was trained with exactly this idea, in a version called TD($\lambda$).

TD targets are biased at first (they lean on estimates that may be wrong), but much less noisy than full returns. That trade-off between bias and variance will follow us through the rest of the module.

$V(s) = 0.5$, the agent gets $r = 1$ and lands in $s'$ with $V(s') = 0$ (terminal). With $\alpha = 0.1$ and $\gamma = 0.9$, what is the new $V(s)$?

  1. 1.0
  2. 0.55
  3. 0.45
  4. 0.6
TD target $= 1 + 0.9 \times 0 = 1$; TD error $= 1 - 0.5 = 0.5$; new value $= 0.5 + 0.1 \times 0.5 = 0.55$. A small step toward the target, not a jump.

Q-learning

Learning $V$ isn't enough to act without a model: to pick the best action from $V$ you'd need to know where each action leads. So Chris Watkins, in his 1989 PhD thesis Learning from Delayed Rewards, applied the TD idea to action values and the Bellman optimality equation:

$$Q(s,a) \leftarrow Q(s,a) + \alpha\,\Big[\, r + \gamma \max_{a'} Q(s', a') - Q(s,a) \,\Big]$$
  • $(s, a, r, s')$: one observed transition: state, action taken, reward, next state.
  • $r + \gamma \max_{a'} Q(s',a')$: the TD target, reward plus the discounted value of the best action at $s'$ (0 if $s'$ is terminal).
  • The bracket is the TD error $\delta$, and $\alpha$ sets how far to move toward the target.

Watkins and Dayan proved in 1992 that tabular Q-learning converges to $Q^*$, provided every state-action pair keeps being tried and the step sizes shrink appropriately. Then the greedy policy $\arg\max_a Q(s,a)$ is optimal.

Off-policy. The agent behaves $\varepsilon$-greedily (it must explore, or it never discovers better actions), but its target uses $\max_{a'}$, the greedy choice, regardless of what it does next. So it learns the values of the optimal policy while following a different, exploratory one. Its on-policy cousin SARSA (Rummery & Niranjan, 1994) instead uses the action actually taken next, $Q(s',a_{t+1})$, and so learns the value of the exploring policy itself.

What makes Q-learning off-policy?

  1. It never explores
  2. It needs a model of the environment
  3. It updates only at the end of each episode
  4. Its target uses $\max_{a'} Q(s',a')$, the greedy action, not the action the behaviour policy actually takes next
The data comes from an exploring policy, but the target always assumes the best next action. That's what lets it learn $Q^*$ from exploratory (or even someone else's) experience.

Explain like I'm 5

You're learning the way to the ice-cream shop in a new town. At every corner you keep a little note: "turning left here gets me ice cream this fast".

You don't wait until you're home to fix your notes. As soon as you turn a corner and see the next street, you think: "oh, the next corner's note says it's close from there", and you update this corner's note right away to match.

Sometimes you try a street you've never walked, just in case it's a shortcut. Over many trips, every corner's note ends up right, and you just follow the best note.

Where it breaks: real Q-learning nudges each note only part of the way ($\alpha$), and in a random world the same corner can lead to different streets, so the notes average over many trips.

In the playground, with $\varepsilon = 0$ and all Q-values starting at 0, why can learning stall?

  1. The discount factor is too high
  2. The learning rate $\alpha$ is zero
  3. Once some actions look best, a purely greedy agent never tries the others, so their estimates (and maybe better routes) are never corrected
  4. Q-learning only works with a neural network
It's the bandit problem from RL.1 again, in every cell. Convergence to $Q^*$ requires every state-action pair to keep being tried.

DQN: from tables to pixels

A table needs one entry per state. An Atari screen is 210×160 pixels in colour, so the number of possible states is astronomical. The fix is function approximation: a neural network $Q_\theta(s,a)$ that takes the state as input and generalizes to states it has never seen. Training it is regression: make $Q_\theta(s,a)$ match the TD target, by gradient descent on the squared TD error.

People had tried this for decades, and it was notoriously unstable: combining function approximation, bootstrapping and off-policy learning (Sutton and Barto call it the "deadly triad") can make the estimates diverge. In 2013 Volodymyr Mnih and colleagues at DeepMind made it work on Atari games from raw pixels (Playing Atari with Deep Reinforcement Learning, 7 games), and in 2015 their Nature paper reached a level comparable to a professional human games tester across a set of 49 games (more than 75% of the tester's score on 29 of them), using the same network and settings for every game. The input was the last 4 frames, downscaled to 84×84 greyscale; a small convolutional network output one Q-value for each of up to 18 joystick actions.

The two stabilizers, in plain words:

  • Experience replay (Lin, 1992; used in both DQN papers): store transitions in a buffer and train on random minibatches. This breaks the correlation between consecutive frames, makes the data look closer to the i.i.d. samples gradient descent expects (P2.2), and reuses every experience many times.
  • Target network (added in the 2015 paper): compute targets with a frozen copy $\theta^-$ that is refreshed only every $C$ steps. Otherwise each update moves the very target it's chasing, like a dog chasing its tail.

What is the job of DQN's target network?

  1. To keep the TD target fixed for a while, so the online network isn't chasing a target that moves with every update
  2. To choose which actions to explore
  3. To store past transitions
  4. To process the pixels into features
The target $r + \gamma \max_{a'} Q_{\theta^-}(s',a')$ uses frozen weights $\theta^-$, copied from $\theta$ only every $C$ steps. Replay (not the target net) stores transitions.

Overestimation and Double DQN

There's a subtle bias hiding in $\max_{a'}$. Suppose all three actions in some state are truly worth 0, but your estimates are noisy: $+0.3$, $-0.2$, $-0.1$. The max picks $+0.3$, so the target says the state is worth $0.3$ when it is worth 0. Noise in either direction is equally likely, but the max systematically selects the lucky overestimates. The error then spreads backwards through bootstrapping, and DQN was shown to grossly overestimate values on several Atari games.

Double Q-learning (van Hasselt, 2010) separates choosing from scoring. Double DQN (van Hasselt, Guez & Silver, 2016) does it with networks DQN already has: the online network picks the best next action, and the target network evaluates it:

$$y = r + \gamma\, Q_{\theta^-}\Big(s',\ \arg\max_{a'} Q_\theta(s', a')\Big)$$

If the online net's favourite action was only lucky noise, the target net's independent-ish estimate of it is usually lower, so the lucky bias mostly cancels. It's a one-line change that improved scores across Atari. Many more fixes followed (prioritized replay, duelling networks, distributional values…), and Rainbow (Hessel et al., 2018) combined six of them.

Why this matters for LLMs: modern LLM post-training mostly uses policy-gradient methods (RL.4, RL.5), not Q-learning. With a vocabulary of 100k+ tokens and a pretrained model that already writes well, it's more natural to adjust the policy directly than to learn a Q-value for every token in every context. But the ideas here are everywhere: PPO's critic in RLHF is trained with TD-style targets, the bias-variance trade-off between bootstrapped and full returns shapes how advantages are computed (RL.5), and the warning about maximizing over noisy estimates is exactly the reward-hacking story of reward models: push hard on an imperfect scorer and you find its lucky overestimates.

Why does $\max_{a'} Q(s',a')$ over noisy estimates tend to overestimate?

  1. Because rewards are usually positive
  2. Because the max preferentially picks whichever estimates happen to be too high
  3. Because $\gamma < 1$
  4. It doesn't: positive and negative errors cancel exactly
Errors average out for a single estimate, but not after a max: $\mathbb{E}[\max_a \hat Q(a)] \ge \max_a \mathbb{E}[\hat Q(a)]$. Double DQN decouples selection from evaluation to cut this bias.
Explain it back · in two or three sentences

Explain the Q-learning update in words, and say why DQN needed experience replay and a target network to make it work with a neural network.

Model answer: After each transition, Q-learning moves $Q(s,a)$ a step $\alpha$ toward the TD target $r + \gamma \max_{a'} Q(s',a')$, the reward plus the best estimated value of the next state. With a neural network, consecutive samples are highly correlated and the target shifts with every weight update, which makes training unstable; replay trains on random past transitions, and a frozen target network holds the target still between periodic copies.
Check yourself

$Q(s,a) = 1.0$, $r = 0.5$, $\max_{a'} Q(s',a') = 2.0$, $\gamma = 0.9$, $\alpha = 0.1$. What is the updated $Q(s,a)$?

  1. 2.3
  2. 1.23
  3. 1.13
  4. 1.05
Target $= 0.5 + 0.9 \times 2.0 = 2.3$; TD error $= 2.3 - 1.0 = 1.3$; new $Q = 1.0 + 0.1 \times 1.3 = 1.13$.

Connect to RL.2: Q-learning's update is a sample-based version of which equation?

  1. The Bellman optimality equation for $Q^*$
  2. The Bellman expectation equation for $V^\pi$
  3. The discounted return with $\gamma = 1$
  4. The policy gradient
$Q^*(s,a) = \mathbb{E}[r + \gamma \max_{a'} Q^*(s',a')]$. Q-learning replaces the expectation with one sampled transition and takes a small step toward it. (TD(0) on $V$ is the sampled expectation equation.)

Connect to P3.1: what does DQN's network output for one input state?

  1. A single number: the state's value
  2. The next frame of the game
  3. A probability for each action, summing to 1
  4. One Q-value per action, so the greedy action is an argmax over one forward pass
The final layer has one output unit per action (up to 18 on Atari). They are value estimates, not probabilities, so there's no softmax.

In Double DQN, which network picks the next action and which scores it?

  1. The target net picks; the online net scores
  2. The online net picks ($\arg\max$); the target net scores it
  3. Both are averaged
  4. A third network is trained just to pick actions
$y = r + \gamma\,Q_{\theta^-}(s', \arg\max_{a'} Q_\theta(s',a'))$. Decoupling selection from evaluation removes most of the max's upward bias.

Key takeaways

  • TD learning updates estimates from the next step's estimate (bootstrapping): no model, no waiting for the episode to end.
  • Q-learning: $Q(s,a) \leftarrow Q(s,a) + \alpha[r + \gamma \max_{a'} Q(s',a') - Q(s,a)]$. Off-policy: it learns $Q^*$ while exploring $\varepsilon$-greedily.
  • DQN = Q-learning with a neural network, plus experience replay and a target network for stability.
  • The max over noisy estimates overestimates; Double DQN lets the online net pick and the target net score.
