State-space models & Mamba

Lesson 3 of Beyond the dense transformer

A Transformer remembers by keeping everything: every token's keys and values, in a cache that grows without end. A state-space model remembers like a reader with a notebook: one fixed-size state, updated as each token goes by. This lesson builds that recurrence from scratch, shows how S4 trains it in parallel and how Mamba made it selective, and is honest about what a fixed-size memory can't do.

By the end you can

  • Run the recurrence $h_t = \bar A h_{t-1} + \bar B x_t,\ y_t = C h_t$ by hand, and compute the same outputs as a convolution.
  • Explain what Mamba's input-dependent ("selective") parameters add, and how a parallel scan keeps training fast.
  • Compare the memory of a KV cache and an SSM state at a million tokens, and say why SSMs struggle with exact recall.
Prerequisites: P6.3 RNNs & LSTMs (hidden states, gates, why recurrence lost to attention) and M1.4 The decoder-only transformer (the block an SSM layer replaces). Helpful but optional: M1.5 KV cache & sampling and P5.4 Convolution.

A model generates its 1,000,000th token. Which needs more memory for that sequence: a Transformer's KV cache or a state-space model's state?

  1. They need the same
  2. The SSM state, since it must summarize a million tokens
  3. The KV cache, by orders of magnitude: it stores every past token, while the SSM state has a fixed size
  4. Neither stores anything about the past
A KV cache grows by one entry per token per layer, reaching roughly 100+ GB for a mid-size model at a million tokens. An SSM's state is the same size at token 10 and at token 1,000,000, typically megabytes.

You paste a 50,000-token phone book into a pure state-space model and ask for one person's number. What is the likely problem?

  1. The fixed-size state can't hold every entry exactly, so the number may be lost or garbled
  2. It will run out of memory
  3. It will be much slower than a Transformer
  4. Nothing; SSMs are perfect at lookups
Compression is the price of a fixed-size memory. Exact recall of arbitrary earlier content is where pure SSMs fall behind attention, which is why most production designs are hybrids (AR.4).

A fixed-size memory: the state-space recurrence

P6.3 ended with a trade-off. RNNs keep a fixed-size hidden state but train one step at a time and forget; Transformers train in parallel and recall anything, but every generated token adds keys and values to a cache that grows forever. In 2020–2021, Albert Gu and colleagues looked for a recurrence that could have both, and found it in control theory. A state-space model (as in Kalman's work from 1960) describes a system whose hidden state $h(t)$ evolves continuously under an input $x(t)$:

$$h'(t) = A\,h(t) + B\,x(t), \qquad y(t) = C\,h(t)$$

Text comes in discrete tokens, so the model discretizes this with a step size $\Delta$. In words: pretend each input is held constant for a time $\Delta$, and work out exactly where the state ends up. (The usual "zero-order hold" rule gives $\bar A = e^{\Delta A}$ and a matching $\bar B$.) A large $\Delta$ lets the state move far toward the new input, forgetting more of the old; a small $\Delta$ barely changes the state. The result is a linear recurrence:

$$h_t = \bar A\,h_{t-1} + \bar B\,x_t, \qquad y_t = C\,h_t$$
  • $x_t$ is one input channel at step $t$ (an SSM layer runs one such recurrence per channel, in parallel), and $y_t$ the output.
  • $h_t$ is the state, a vector of $N$ numbers ($N = 16$ in Mamba, 64–256 in Mamba-2). It is the model's entire memory of the past.
  • $\bar A$ ($N \times N$, diagonal in practice) decides how the state decays and mixes; $\bar B$ writes the input into the state; $C$ reads the output out.

Unlike the RNN in P6.3 there is no tanh between steps. That linearity is what makes the parallel tricks below possible. Early structured SSMs initialized $A$ with HiPPO (Gu et al., 2020), a matrix designed so the state keeps a compressed summary of the whole history.

Worked example

One-number state: $\bar A = 0.5$, $\bar B = 1$, $C = 2$, inputs $x = (1, 0, 0, 1)$, starting from $h_0 = 0$.

  1. $h_1 = 0.5 \cdot 0 + 1 = 1$, so $y_1 = 2$.
  2. $h_2 = 0.5$, $y_2 = 1$. Then $h_3 = 0.25$, $y_3 = 0.5$: the memory of the first input halves each step.
  3. $h_4 = 0.5 \times 0.25 + 1 = 1.125$, so $y_4 = 2.25$: new input plus a fading echo of the old.

In the discretized SSM, what happens when the step size $\Delta$ is large?

  1. The state ignores the new input
  2. The state moves strongly toward the new input and forgets more of what it held
  3. The state grows by one entry
  4. The output becomes zero
$\Delta$ is how long the input is "held". Long hold: the decay $e^{\Delta A}$ shrinks the old state a lot and the input dominates. Short hold: the state barely changes. Mamba makes $\Delta$ depend on the token.

S4: train as a convolution, generate as an RNN

A recurrence looks sequential, but this one isn't, because it's linear and its parameters don't change over time. Unroll it (with $h_0 = 0$):

$$y_t = C\bar B\,x_t + C\bar A\bar B\,x_{t-1} + C\bar A^2\bar B\,x_{t-2} + \dots = \sum_{j=0}^{t-1} \bar K_j\,x_{t-j}, \qquad \bar K = \big(C\bar B,\ C\bar A\bar B,\ C\bar A^2\bar B,\ \dots\big)$$

So the whole output is one long convolution of the input with a fixed kernel $\bar K$ (P5.4). The kernel can be computed once, and the convolution done for every position at once with an FFT in about $L \log L$ steps for a length-$L$ sequence. That's the trick of S4 (Gu, Goel & Ré, 2021, "Efficiently Modeling Long Sequences with Structured State Spaces"):

  • Training: use the convolution view, parallel over the sequence, like a Transformer.
  • Generation: use the recurrent view: each new token costs a fixed amount of work and the memory is just $h_t$, whatever the length.

S4's other contribution was a structured $A$ (diagonal plus low-rank) that made computing $\bar K$ fast and stable. It was the first model to solve Path-X, a 16,384-step task in the Long Range Arena benchmark where earlier efficient Transformers did no better than chance. Follow-ups (DSS, S4D, 2022) showed a plain diagonal $A$ works nearly as well, which is what later models use.

Worked example: the same numbers, as a convolution

For $\bar A = 0.5$, $\bar B = 1$, $C = 2$: $\bar K = (2,\ 1,\ 0.5,\ 0.25)$. With $x = (1, 0, 0, 1)$:

$y_4 = \bar K_0 x_4 + \bar K_1 x_3 + \bar K_2 x_2 + \bar K_3 x_1 = 2 \cdot 1 + 1 \cdot 0 + 0.5 \cdot 0 + 0.25 \cdot 1 = 2.25$, exactly what the recurrence gave.

But on language, S4-style models still trailed Transformers. Their kernel is the same for every input: the model weighs "3 tokens ago" identically whether that token was "the" or a person's name. It can't decide, based on content, what to keep.

Why can S4 be trained as a convolution?

  1. Because it uses attention internally
  2. Because its state is very small
  3. Because it processes only short sequences
  4. Because the recurrence is linear and $\bar A$, $\bar B$, $C$ are the same at every step, so the output is the input convolved with a fixed kernel $C\bar A^j \bar B$
Time-invariant and linear means "the effect of the input $j$ steps ago" is a fixed number $\bar K_j$. That's the definition of a convolution, which runs in parallel.

Mamba: making the state selective

Mamba (Gu & Dao, 2023, "Mamba: Linear-Time Sequence Modeling with Selective State Spaces") lets the parameters depend on the current token:

$$\Delta_t = \mathrm{softplus}(W_\Delta x_t), \qquad B_t = W_B\,x_t, \qquad C_t = W_C\,x_t, \qquad \bar A_t = e^{\Delta_t A}$$

$A$ itself stays a learned diagonal matrix with negative entries (so $e^{\Delta_t A}$ is a decay between 0 and 1). Now each token decides how it is treated: a large $\Delta_t$ means "reset and store me", a small $\Delta_t$ means "skip me, keep the memory". $B_t$ and $C_t$ choose what to write and what to read. This is the LSTM's gating idea (P6.3) in a linear recurrence, and Mamba showed it solves synthetic tasks S4 couldn't, such as selectively copying tokens and induction-head-style lookups.

The cost: with parameters that change every step, there's no fixed kernel and no convolution. Mamba's answer is a hardware-aware parallel scan. Each step has the form $h_t = a_t h_{t-1} + b_t$, and two such steps compose into one of the same form: applying $(a_1, b_1)$ then $(a_2, b_2)$ equals $(a_2 a_1,\ a_2 b_1 + b_2)$. Because that combination is associative, the steps can be combined in a tree, so a GPU computes all $L$ states in about $\log_2 L$ rounds instead of $L$. In the spirit of FlashAttention (M5.4), Mamba's kernel keeps the large expanded states in fast on-chip SRAM, never writes them to main GPU memory, and recomputes them in the backward pass.

The Mamba paper reported about 5× higher generation throughput than a Transformer of similar size, linear scaling in sequence length, and a 3B-parameter Mamba matching Transformers about twice its size on the language-modelling benchmarks it tested.

Explain like I'm 5

Two children read the same very long storybook. The first one, every time they read a new page, flips back through every page so far. Their desk disappears under piles of books, and each page takes longer than the last. That's a Transformer.

The second child reads forward and keeps one small notebook of running notes: who's who, where they are, what's happening. Each page takes the same time, and the notebook never gets bigger. That's a state-space model. Mamba's trick is a child who decides, page by page, what's worth writing down and what to rub out.

Where it breaks: ask the second child for the exact words on page 12, and if they didn't note them, they're gone. Real models also have dozens of "notebooks", one set per layer.

What does making $\Delta$, $B$ and $C$ input-dependent cost Mamba, and how does it pay?

  1. It loses the fixed convolution kernel, so it trains with a hardware-aware parallel scan instead
  2. It loses the fixed-size state, so it needs a KV cache
  3. It becomes quadratic in sequence length
  4. Nothing; the convolution still works
A time-varying recurrence has no single kernel. But $h_t = a_t h_{t-1} + b_t$ steps combine associatively, so a parallel scan computes all states in about $\log L$ rounds, and the state stays fixed-size at inference.

A million tokens, Mamba-2 and the recall problem

Here is the payoff in numbers. A Transformer's KV cache stores $2 \times L \times n_{kv} \times d_{\text{head}} \times b$ bytes per token (M1.5). An SSM layer stores its state, $d_{\text{inner}} \times N$ numbers (one $N$-sized state per channel), plus a few recent inputs for Mamba's short convolution, and that's it.

Worked example

  1. Transformer (Llama 3.1 8B: 32 layers, 8 KV heads, head size 128, bf16): $2 \times 32 \times 8 \times 128 \times 2 = 131{,}072$ bytes per token. At 1,000,000 tokens: about 131 GB, for one sequence.
  2. Mamba (the 2.8B model: 64 layers, $d_{\text{inner}} = 5120$, $N = 16$): state $64 \times 5120 \times 16 \approx 5.2$M numbers, plus about 1.3M for the convolution buffers. About 6.6M numbers, roughly 26 MB even in 32-bit floats.
  3. The SSM's 26 MB is the same at token 10 and token 1,000,000. And each new token costs a fixed amount of work, while attention must read all $t$ cached keys.

These models are different sizes, so read it as a scaling comparison, not a contest: one grows linearly with the context, the other is flat.

Mamba-2, the duality with attention, and the recall problem

Mamba-2 (Dao & Gu, 2024, "Transformers are SSMs") restricted $\bar A_t$ to a single number per head times the identity. Then the whole layer can be written as $y = M x$, where $M$ is a lower-triangular matrix whose entry for output $t$ and input $s \le t$ is $C_t^\top B_s$ times the product of the decays between them. That is exactly the shape of causal attention with a decay mask, with $C$ playing the query, $B$ the key and $x$ the value. Dao and Gu call this structured state-space duality: the same layer can run as a recurrence (constant memory) or as masked, attention-like matrix multiplies over chunks of the sequence, which use GPU tensor cores well. Mamba-2 used much larger states ($N$ of 64 to 256) and reported a core layer 2–8× faster than Mamba-1's scan. Work continues: Mamba-3 (Lahoti et al., 2026) revisits the discretization and the state update with inference speed in mind.

Now the weakness. A fixed-size state must compress the past, and compression loses detail. Tasks that need exact recall of arbitrary earlier content, like copying a long string, looking up a number in a pasted table, or associative recall ("what came after this key?"), are where pure SSMs fall behind:

  • Jelassi et al. (2024, "Repeat After Me") proved a small Transformer can copy strings of exponential length, while any fixed-state model is limited by its state size, and found trained Transformers learned copying much faster in practice.
  • The Zoology study (Arora et al., 2023) found that most of the language-modelling gap between attention and efficient recurrent models came from associative recall.
  • An NVIDIA study (Waleffe et al., 2024) trained 8B pure Mamba and Mamba-2 models alongside a Transformer on the same data; the pure SSMs lagged on tasks needing in-context recall, like five-shot MMLU and phone-book lookup, while a hybrid with a few attention layers matched or beat the Transformer.

Hence the next lesson: mix a few attention layers in.

Why this matters for LLMs: SSM layers buy constant memory and constant time per generated token, which matters for very long inputs, long agent sessions and cheap high-batch serving. As of 2026 they show up mainly inside hybrids, models that interleave Mamba-style layers with a few attention layers, rather than as pure SSM LLMs. When a model card says "Mamba-2 layers" or "linear attention", expect a smaller long-context memory bill and check its long-context recall scores (AR.5).

According to Mamba-2's state-space duality, an SSM layer with scalar decay is equivalent to…

  1. A convolutional network with a fixed kernel
  2. A form of causal linear attention with a decay mask, where $C$ acts like the query and $B$ like the key
  3. A mixture of experts
  4. Standard softmax attention
The matrix $M_{ts} = C_t^\top B_s \times$ (decays from $s$ to $t$) has the form of masked attention scores without a softmax. That's why SSMs and linear attention (AR.4) turn out to be close relatives.
Explain it back · in two or three sentences

How can an SSM train in parallel yet generate with constant memory, and what does Mamba add?

Model answer: The SSM recurrence $h_t = \bar A h_{t-1} + \bar B x_t$, $y_t = C h_t$ is linear, so the outputs can be computed for all positions at once: as a convolution with the kernel $C\bar A^j\bar B$ when the parameters are fixed (S4), or with an associative parallel scan when they vary. At generation time the same layer runs as a recurrence, carrying only the fixed-size state $h_t$. Mamba makes $\Delta$, $B$ and $C$ depend on each token, so the model can choose what to store and what to skip, at the price of needing the scan instead of a convolution; the fixed-size state still makes exact recall of distant details hard.
Check yourself

$\bar A = 0.8$, $\bar B = 1$, $C = 1$, inputs $x = (1, 1)$, $h_0 = 0$. What is $y_2$?

  1. 2
  2. 1.8
  3. 1.64
  4. 0.8
$h_1 = 1$, $h_2 = 0.8 \times 1 + 1 = 1.8$, and $y_2 = C h_2 = 1.8$. As a convolution: $\bar K = (1, 0.8)$, so $y_2 = 1 \cdot 1 + 0.8 \cdot 1$.

Interleaving with P6.3: what is the key difference between an SSM layer and the classic RNN $h_t = \tanh(W h_{t-1} + U x_t)$?

  1. The SSM has no hidden state
  2. The SSM uses attention between steps
  3. The RNN's state is larger
  4. The SSM's step is linear (no tanh between steps), which allows the convolution and parallel-scan tricks for parallel training
The nonlinearity forces an RNN to compute $h_1$, then $h_2$, and so on. A linear recurrence can be unrolled algebraically. SSMs put their nonlinearities around the recurrence (projections, gates, MLPs), not inside it.

In Mamba, a token produces a very small $\Delta_t$. What happens to the state at that step?

  1. It barely changes: $e^{\Delta_t A}$ is close to 1 and little of the token is written, so the token is effectively skipped
  2. It resets to zero
  3. It doubles in size
  4. It copies the token exactly
Small $\Delta$ means a short "hold": almost no decay and almost no input. That's how Mamba ignores filler tokens and keeps its memory for what matters.

Which task is a pure SSM most likely to get wrong compared with a Transformer of similar size?

  1. Continuing a story in the same style
  2. Generating text quickly at very long context
  3. Returning the exact 40-character ID that appeared once, 30,000 tokens earlier
  4. Next-token prediction on ordinary prose
Exact recall of arbitrary distant content needs that content to be stored. Attention keeps it in the KV cache; a fixed-size state may have overwritten it.

Key takeaways

  • A discretized SSM is a linear recurrence: $h_t = \bar A h_{t-1} + \bar B x_t$, $y_t = C h_t$, with step size $\Delta$ controlling how much each input moves the state.
  • S4: fixed parameters make it a convolution with kernel $C\bar A^j \bar B$, so it trains in parallel and generates as an RNN with constant memory.
  • Mamba makes $\Delta$, $B$, $C$ input-dependent (selective) and trains with a hardware-aware parallel scan.
  • At a million tokens a KV cache can reach ~100+ GB per sequence; an SSM state stays at megabytes. Mamba-2 shows SSMs are a form of masked linear attention.
  • The price is lossy memory: exact recall and copying from far back are weak spots, which hybrids fix.
